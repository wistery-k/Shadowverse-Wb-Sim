# 候補の打ち比べ調査（`npm run svwb -- survey`）

自己対戦の局面を無作為に取り、今の AI が作れる候補を、同じ乱数で最後まで打ち比べる調査。2026-11-11 から
（審査の文書「AI の設計の審査と今後の方針」課題点 3「先にやること: 候補の打ち比べ調査」、[STATE.md](STATE.md)「次」の 2）。

- **何を測るか**: 伸びしろの 3 つの層（審査の文書の課題点 3）のうち、層 B「AI が作れる候補の中での選び直し」の大きさ。
  AI が手を選んだ後に、候補ごとに最後まで何十回も打って一番良いものを選び直したら、1 試合あたり何ポイント得か。あわせて、はっきりした見落としの回数と、問題集に足す局面
- **判定役は最後まで打った勝ち負け**: 人間の記録にも、打った人の強さにも頼らない。続きは両方の席とも今の AI が打つので、
  「今の AI を 1 段だけ改善した打ち手」の得を測る（今の AI が両方の席で同じように読み違える局面は直らない。審査の文書の前提の但し書き）
- **シミュレータの中の試合だけ**: 局面は今の既定の AI どうしの自己対戦からだけ取る。実際の対戦の局面を入れる口は無い（CLAUDE.md「ソフト打ち」）

本体は `rust/engine/src/runner/survey.rs`。候補を作るのは `SearchAgent::survey_plans`（`rust/engine/src/ai/search.rs`）。

## 何をするか

1. **局面**: 今の既定の AI どうしの試合 g（デッキ・席・シードは `svwb ai-play`・`deep-gap` と同じ `ai_game_setup`）を打ち、
   両方の席の自分のターンの最初の局面から、試合番号と手の番号で決まる乱数で `--rate` の割合を選ぶ。**差の大きさでは選ばない**
   （差の大きい局面だけを選ぶと、たまたま悪いほうを引いた分が混ざる。deep-gap の 150 局面は点数の差 15.2 が最後まで打って 8.2 だった）
2. **候補**: 試合でその局面を考えたときと同じ乱数で今の AI に考えさせ（試合で打った手と同じ手を選ぶ。違えば行に `match: false`）、次を候補にする
   - **AI が読み直す候補**: ターン末の点数の上位 4 つの最初の手と、drawSplit が足す引く手（AI はこの中から選ぶ）
   - **足す候補**: 同じ決定化のビームの終局面から、ターン末の点数の高い順に、使うカードの組（手札から出すカード・融合の素材の種類）が
     それまでの候補のどれとも違い、打つ手も違う並びを `--extra` 個（既定 4）。評価の読み違いで下に落ちている手を拾うため
     （同じ最初の手でも別の並びを拾う。deep-gap の試合 486 のジャンヌのように、最初の手ごとに 1 つしか読み直さないと落ちる並び）
3. **打ち方**: 候補ごとに `--m` 回（既定 32）最後まで打つ。r 回目は、手番の側から見た決定化（相手の手札・山札の中身と順番、乱数の状態）と
   AI の乱数がどの候補でも同じ。候補は、AI がその並びを選んだものとして打つ: 最初の手を打ち、次の判断からは局面が予想どおりなら並びの続きを打つ
   （並びは最初の引く手・ランダムな手までで、その先と並びを打ち終えた後は AI が考え直す。リーサルを見つければそれを打つ）。続きは両方の席とも今の既定の AI
4. **二段目（確かめ）**: 一段目の 32 回で、AI の選んだ候補との勝率の差が最も大きい候補の差が `--flag` ポイント（既定 10）以上なら、
   その候補と AI の選んだ候補だけを、一段目と重ならない乱数でさらに `--confirm` 回（既定 96）打つ

## 決まり（回す前に決めたこと。2026-11-11）

結果を見てから変えない。変えるなら、新しい決まりとして書き足し、前の決まりの結果も残す。

| 出すもの | 決まり |
| --- | --- |
| 打ち比べで選び直す得（1 局面） | 一段目の 32 回を偶数回と奇数回に分け、片方で勝ちの最も多い候補を選び（同じなら AI の選んだ候補）、もう片方で AI の選んだ候補との勝率の差を測る。両方の向きの平均。選ぶのに使った回で測らないので、選んだ偏りが入らない（16 回で選ぶ打ち手の得なので、もっと回数を掛けて選ぶ打ち手の得より小さい。下限） |
| 1 試合あたり | 1 局面あたりの得（打ち比べなかった局面は 0）× 1 試合 1 席の自分のターンの最初の局面の数（選ばなかった局面も数える）。片方の席が全部の自分のターンで選び直したときの見積もり（局面どうしの重なりは見ない） |
| 上位 4 つだけと 8 つ | 選べる候補を「AI が読み直す候補」だけにしたものと、足す候補を含めた全部 |
| はっきりした見落とし | 二段目の回だけで、選び直した候補と AI の選んだ候補の差が 15 ポイント以上、かつ差の標準誤差（回ごとの差のばらつきから）の 3 倍以上。一段目の差は使わない |
| 問題集に足す局面の候補 | はっきりした見落としの局面（審査の文書の「打ち比べの差が 15 ポイント以上で、誤差の 3 倍を超えるもの」）。合格の条件は、局面と 2 つの並びを見て `npm run misses -- add` で手で書く（[misses.md](misses.md)） |
| 内訳 | デッキ（手番の側）、自分のターン（1〜3・4〜6・7〜9・10〜）、手の種類（一段目の 32 回で勝ちの最も多い候補と AI の選んだ候補の違い: 出すカード／進化・超進化／融合・能力・エクストラPP／攻撃先・手の順番だけ。読み直した候補か足した候補か） |

- 見落としの数え方は控えめ（下限）: 一段目で差が 10 未満に出た局面は二段目に回らない。本当の差が 15 の局面は、一段目の 32 回（差の標準誤差 10 ポイントほど）で
  10 以上に出るのが 7 割ほどで、二段目で 15 以上に出るのは半分ほど
- 打てなかった回（`x`。並べ直した局面で最初の手が打てない・途中で止まった）は、その回だけ両方の候補から除く（0 のはず）
- 引き分けは 0.5 勝

## 3 つの層と、どの結果ならどうするか

| 結果（1 試合あたり、8 つの候補で選び直す得） | 読み方 | 次にすること |
| --- | --- | --- |
| 大きい（3 ポイント以上で、0 から標準誤差の 2 倍以上離れる） | 層 B が大きい。打ち比べで選ぶ打ち手は、今の AI よりはっきり強い | 打ち比べを先生役にする（検討モード、打ち比べの結果を学習に戻す）。足した候補の分が大きければ、読み直す候補に使うカードの組の違う並びを入れる案を compare で測る |
| 中くらい（1〜3 ポイント） | 層 B はあるが小さい | 見落としの局面を問題集に足し、手の種類の内訳から直す所を絞る。読み直しの改善は、内訳の多い所だけ束ねて測る |
| 小さい（1 ポイント未満、上の端も 1.5 未満） | 層 B はほぼ尽きた（読みを増やす層 A も尽きている）。残りは層 C（AI が候補にも作れない手） | 選び直しに手間をかけず、補正の入力の追加と広いデッキでの学び直し（STATE.md「次」の 3）に進む |

- 上位 4 つだけの得と 8 つの得の差は、足した候補の分。差が小さければ、AI の候補の作り方（ビーム）は足りていて、取りこぼしは選ぶ段（読み直し）にある
- はっきりした見落としが 1 試合 1 席 0.1 回以上なら、問題集に足して手の種類を見る。ほぼ 0 なら、AI は自分の候補の中ではっきりしたミスをまれにしかしない

## コマンド

```sh
npm run svwb -- survey run --out 結果.jsonl --games a-b [--rate 0.1] [--m 32] [--extra 4] [--confirm 96] [--flag 10] [--batch 8]
npm run svwb -- survey report 結果.jsonl… [--label 名前] [--no-ledger] [--top 20] [--states <フォルダ>]
```

| 引数 | 既定 | 意味 |
| --- | --- | --- |
| `--games a-b` | （要る） | 打つ自己対戦の試合番号の範囲 |
| `--rate` | 0.1 | 自分のターンの最初の局面を選ぶ割合（1 試合に両方の席で 19 局面ほどなので、0.1 で 1 試合 2 局面ほど） |
| `--m` | 32 | 一段目に候補ごとに打つ回数 |
| `--extra` | 4 | 足す候補の数 |
| `--confirm` | 96 | 二段目に打つ回数（AI の選んだ候補と、差の最も大きい候補の 2 つ） |
| `--flag` | 10 | 二段目に回す、一段目の差（ポイント） |
| `--batch` | 8 | まとめて打って書く試合の数（止めたときに失うのは書いていない分だけ） |
| `report --label` | なし | 台帳の名前 |
| `report --no-ledger` | なし | 台帳に書かない |
| `report --top` | 20 | 問題集に足す候補を出す数 |
| `report --states <フォルダ>` | なし | 問題集に足す候補の局面を `g<試合>-i<手>.json`（状態の JSON）で書く。`npm run misses -- add --state` に渡せる |

- `run` は出力に既にある試合を飛ばす（同じ引数で再開できる）。試合の行の無い局面の行（途中で止めたもの）は、再開のときに消す
- 結果は並列数によらず同じ（試合・局面・回ごとにシードで決まる）
- `report` は回すたびに台帳 `docs/ledger.jsonl` に 1 行足す（`kind` は `survey`。形は [ledger.md](ledger.md)）

## 出力（JSON Lines）

局面の行（1 局面 1 行）:

| 項目 | 中身 |
| --- | --- |
| `g`・`i`・`p` | 試合番号・手の番号（その手の前の局面）・手番の側 |
| `turn`・`own`・`first`・`deck`・`opp`・`maxPp`・`hp`・`oppHp` | ターン（両者を通した番号）・自分のターン・先攻か・デッキ・相手のデッキ・PP 最大値・体力 |
| `view` | 手番の側から見える局面の説明 |
| `state` | 局面（状態の JSON。見落とし問題集の問と同じ形。AI を変えても局面はこのまま使える） |
| `skip` | 打ち比べなかった理由（`lethal`: リーサルを見つけた、`one-action`: 打てる手が 1 つ、`one-plan`: 候補が 1 つ、`no-chosen`: AI の手が候補に無い）。打ち比べたら null |
| `match` | 考え直した AI の手が試合で打った手と同じか |
| `terminals` | ビームの終局面の数 |
| `plans` | 候補（`top` 読み直す候補か・`chosen` AI の選ぶ手か・`rank` ターン末の点数の順位・`turnEnd`・`value` 選ぶときの値・`steps` 打つ手・`text` その説明・`full` ビームの終局面までの並び・`used` 使ったもの） |
| `ai`・`m`・`w` | AI の選んだ候補の添字・一段目の回数・候補ごとの勝ち負け（1 回 1 文字。`1` 勝ち・`0` 負け・`d` 引き分け・`x` 打てなかった） |
| `confirm` | 二段目（`c` 候補・`d1` 一段目の差・`n` 回数・`ai`・`alt` 勝ち負け）。回さなければ null |
| `rollouts`・`sec` | 打った回数と、かかった秒（スレッド 1 本の秒の和） |

試合の行（`"game": true`）: 試合番号・シード・デッキ・`turnStarts`（席ごとの自分のターンの最初の局面の数）・`sampled`・勝者・設定・コミット・マシン・スレッド数。
