# 対戦の速さ（定期的なプロファイリング）

探索 AI どうしの対戦が、デッキごとに 1 試合何秒かかり、思考のどの処理に時間を使っているかを測って記録する表。
速さを変える変更（探索の幅を広げる、エンジンを速くする、等）の前後や、時期を置いて測り、遅くなっていないか・どこを速くすれば効くかを見る。
初回の結果と高速化の余地の検討は `docs/ai-notes.md`「対戦の速さを定期的に測る」。

## 測り方

```sh
npm run profile                                   # 今の既定の探索 AI どうしで 98 試合。報告は rust/target/profile-report/report.md
npm run profile -- --label 名前 --record          # 下の表に 1 行足す
npm run profile -- --time-only                    # 時間だけ（内訳を測るビルドを作らない。半分の時間）
npm run profile -- --opts '{"beamWidth":128,"maxDepth":8}'   # 設定を変えて測る（compare の設定と同じ形）
npm run profile -- --rhino                        # リノセウスエルフはリノセウス用 AI で打つ（ブラウザの AI対戦・自動対戦と同じ）
```

- 試合は `compare` と同じデッキの組で、試合番号ごとに席とデッキを入れ替えて 2 試合（両方の席が同じ設定）。既定の `--games 49` で、
  比較用の 7 デッキの 7×7 の組（同じデッキどうしも含む）を 2 回ずつ、98 試合打つ。試合はシードで決まるので、AI が同じなら毎回同じ試合になる
- 本体は `svwb profile`（`rust/engine/src/runner/profile.rs`）。`npm run profile`（`scripts/profile.mjs`）は、測らないビルドで時間を、
  測るビルド（`--features profile`。`rust/target/profile` に作る）で処理ごとの内訳を取り、同じ試合になったことを確かめて 1 つの報告にまとめる
- かかる時間: このスレッドの環境（Claude のクラウド環境、4 スレッド）で、2 回の実行がそれぞれ 80 秒ほど。初回はビルドが 2 回（それぞれ 2 分ほど）
- 時間は試合を打ったスレッドの経過時間なので、並列数（`THREADS`）と CPU で変わる。表の行を比べるのは同じ環境どうし。
  同じビルドを 2 回回したぶれは、このスレッドの環境で 5% ほど（76.5 秒と 80.8 秒）
- 変更の前後を比べる: 前のビルドの `svwb profile --json 前.json` を、後のビルドの `svwb profile --baseline 前.json` に渡すと、
  同じ試合になったかを確かめて（違えばエラー）思考の時間の比を出す。結果を変えない高速化の確かめに使える

## 内訳の測り方

測りたい処理の始めに `let _p = prof::scope(Sec::X);` を置き、その処理を抜けるまでの時間を、呼び出しの入れ子ごとに足す（`rust/engine/src/prof.rs`）。
同じ処理でも、自分のターンのビームの中と相手のターンの読みの中は別に数える。測らないビルドでは何もしない（消えるので速さは変わらない）。
測るビルドは 1 回あたり数十ナノ秒かかり、思考の時間が 1.1 倍ほどになる。細かく呼ばれる処理（手を打つ・局面の複製 等）ほど多めに出る。

| 処理 | 測っている所 |
| --- | --- |
| 思考 | AI が 1 手を選ぶ（`choose_action`） |
| マリガン | 探索 AI のマリガン（`turn1` なら返し方 16 通り × 引き直し 100 回を 3 ターン目まで貪欲法で打ち進める） |
| リーサル探索 | `find_lethal`。中に、ビーム（`search_lethal`）・全探索（`search_exact_lethal`）・与えうるダメージの上限（`damage_bound`） |
| ビーム | ターン末までのビームサーチ（`turn_end_bests`）。思考の直下は自分のターン、読み直しの中は相手のターン |
| 読み直し | ターン末の点数の上位 4 つを、相手の手札を 12 通り引き直して相手のターンまで読む（`plan_turn` の読み直し）。中の「相手のターン」が `simulate_opponent_turn` |
| 展開する手 | ビームで展開する手の一覧（`Planner::expand`。合法手から下位互換の攻撃・手札の同じカードを除く） |
| 子の採点 | ビームの子の点数（`Planner::score`）。中に、合流する相打ち（`settle_converging_trades_with`）・ターン終了時の処理（`resolve_turn_end`）・手で作った評価（`evaluate_with`）・学習した補正（`ValueNet::eval`） |
| 幅まで絞る | ビームの子を点数で並べ、同じ局面を除いて幅まで残す。中の「同じ局面の判定」が `TurnOrderSet::add` |
| 手を打つ | `apply_legal`（局面の複製と効果の解決）。中の「局面の複製」が複製だけ |
| 合法手・決定化・貪欲法・並びの打ち直し | `legal_actions`・`determinize`・`choose_greedy`・`Planner::steps_of` |

## 報告の見方

- **デッキごとの 1 試合の時間**: 思考は、そのデッキを持った側が 1 試合で考えた時間。試合は、そのデッキが出た試合の両者の思考の合計
  （同じデッキどうしの試合も 1 試合と数える）。読み直しは相手のデッキのターンを打つので、思考の時間には相手のデッキの重さも入る
- **デッキごとの内訳**: そのデッキの思考の時間に対する割合。考え直し/試合は自分のターンのビームを打った数（前に選んだ並びの続き・リーサルの続きは数えない）
- **処理ごとの内訳**: 思考の時間（両方の席の合計）に対する割合。字下げはどの処理の中で呼ばれたか。0.5% 未満の行は省く
- **処理の種類ごとの合計**: 自分の時間（中で測った処理を除いた時間。どこで時間を使っているか）と、含む時間（どこで呼ばれたかによらず足したもの）
