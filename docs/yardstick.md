# 強さの物差し

AI の版ごとに、**固定した相手**との勝率を記録する表。`npm run compare` は 2 つの設定を直接比べるので、
「今の AI が前の AI より強いか」は分かっても、何回も改良を重ねたときに全体でどれだけ伸びたかは追いにくい。
相手を動かさずに同じ試合を打てば、版どうしを同じ物差しで並べられる。相手は弱いものと強いものの 2 つ。

## 相手

### 物差し（`--ref classic`、既定）

学習した補正を入れる前の探索 AI（2026-10-16 の `search-classic`）を凍結したもの。設定と評価関数の重みは
`rust/engine/src/runner/yardstick.rs` の `reference_options` に書き写してあり、探索 AI の既定や `SEARCH_WEIGHTS` を変えても動かない。

- 学習した補正なし、相手のターンは貪欲法で読む、決定化 3 回それぞれでビームを打ち最初の手ごとに 3 つまで読み直す（2026-10-16 より前の既定）
- AI の一覧（`rust/engine/src/ai/registry.rs`）にも `yardstick` として載せてあり、web の「人間との比較」タブで相手に選べる（既定）
- 今の AI はこの相手に 80% 勝つので、強い相手にだけ効く改善（相手のターンの読みを強くする、等）はこの表では動きにくい。
  例えば補正 s2b は今の AI との直接の比べで +1.5 ポイントだったが、この表では 79.8% → 80.1% だった

### 強い相手の物差し（`--ref strong`、2026-10-22 から）

2026-10-22 の既定の探索 AI（補正 s2b・相手のターンを幅 16 のビームで読む・相手の手札を 12 通り引き直す）を凍結したもの。
設定は `strong_reference_options` に全項目を書き写し、補正は `rust/engine/yardstick/strong-1-net.json`（その日の `data/value-net.json` の写し）から読む。
既定の補正を学び直しても、探索の既定を変えても動かない。

- 組の 2 試合を同じシードで打つ（`compare` の既定の鏡）。凍結した日の既定の AI はちょうど 50.0% になる。この表の 50% を超えた分が、その日からの伸び
- デッキ別の列は、その日の既定の AI でもデッキの強さで 40〜62% に散る（同じ AI どうしなので、デッキの相性だけが出る）。デッキ別は 50% とではなく、表の 1 行目と比べる
- ほぼ同じ強さの相手なので、`compare` と同じく小さな差まで測れる（2000 試合で標準誤差 1 ポイントほど）。1 回の測定は 4 並列で 20 分ほど（物差しの 3 倍ほど）
- ブラウザでは使えない（補正をファイルから読むため。AI の一覧には載せていない）

### 指紋

どちらの相手も、ルール・カード能力・評価関数や探索のコード・マリガンのモデル・貪欲法の重み（`DEFAULT_WEIGHTS`）を変えると手が変わる。
そこで相手どうしの決まった 14 試合の手順のハッシュ（指紋）を保存し、`cargo test`（`rust/engine/tests/yardstick.rs`）と記録の前に確かめる。

- 指紋が変わったとき:
  - AI の変更が相手に漏れた（例: 評価関数のコードに新しい項を足し、既定で効くようにした）なら、相手では効かないように `reference_options`・`strong_reference_options` か重みを直して戻す
  - ルールやカード能力の修正などで戻せない・戻すべきでないなら、版（`VERSION`・`STRONG_VERSION`）を上げて指紋（`FINGERPRINT`・`STRONG_FINGERPRINT`）を書き直す。表は新しい節から始まる。
    違う版の行どうしは比べず、新しい版では今の既定と主な版を測り直す
- 強い相手は探索のコードを多く使うので、探索を変えると弱い相手より指紋が変わりやすい。新しい読み方は設定の項目にして既定を切っておけば、相手は動かない

## 測り方

```sh
npm run yardstick -- --opts '{}' --games 1000                          # 今の既定の探索 AI（2000 試合、4 並列で数分）
npm run yardstick -- --opts '{}' --games 1000 --label "名前" --record  # 物差しの表に 1 行足す
npm run yardstick -- --ref strong --opts '{}' --games 1000 --label "名前" --record  # 強い相手の物差しの表に 1 行足す（4 並列で 20 分ほど）
npm run yardstick -- fingerprint [--ref strong]                        # 相手の指紋だけ出す
```

- `--opts` は `npm run compare` の設定と同じ形（`{}` が今の既定。`"valueNet"` 等も使える）
- 試合は 7 デッキ、同じデッキの組で席とデッキを入れ替えて 2 試合ずつ（`--games 1000` で g0〜999 の 2000 試合）。
  物差しは compare の `--no-mirror` と同じ組み方（組の 2 試合は別のシード）。compare は 2026-10-22 から組の 2 試合を同じシードで打つ（鏡）が、表の数字を前と比べられるように、物差しは前の試合のまま。
  強い相手の物差しは鏡で打ち、標準誤差は組ごとの勝ち数のばらつきから出す（compare と同じ）。
  相手は固定なので、同じ `--games`・`--start` なら行どうしは同じ試合（同じシード・同じデッキの組）で比べたことになる
- 2000 試合の標準誤差は 1 ポイントほど。差が 2〜3 ポイントより小さければ、同じ物差しでも結論は出さない（勝率の採否はこれまでどおり `npm run compare` で決める）
- 「コミット」の末尾の `+` は、コミットしていない変更がある状態で測ったもの
- デッキ別の列は、測った AI がそのデッキを使ったときの勝率（相手のデッキは 7 つすべてを含む）
- 「1 試合」は、並列で打った全体の時間を試合数で割ったもの（測った AI と相手の両方の思考を含む。4 並列の環境で測った値）

AI の改良を採用したら、その版を `--record` で両方の表に足す。

物差し 1 の最初の 4 行は、2a0a0d7 のコードで既定の設定をその日付の既定に戻して測ったもの（その日付のコードそのものではない。
例えば 2026-10-16 に足した dominance は 4 行とも入っている）。学習した補正・相手のターンのビームサーチ・読み方の変更が、それぞれ物差しの上でどれだけ効いたかの目安。
