# 強さの物差し

AI の版ごとに、**固定した相手**との勝率を記録する表。`npm run compare` は 2 つの設定を直接比べるので、
「今の AI が前の AI より強いか」は分かっても、何回も改良を重ねたときに全体でどれだけ伸びたかは追いにくい。
相手を動かさずに同じ試合を打てば、版どうしを同じ物差しで並べられる。

## 相手

学習した補正を入れる前の探索 AI（2026-10-16 の `search-classic`）を凍結したもの。設定と評価関数の重みは
`rust/engine/src/runner/yardstick.rs` の `reference_options` に書き写してあり、探索 AI の既定や `SEARCH_WEIGHTS` を変えても動かない。

- 学習した補正なし、相手のターンは貪欲法で読む、決定化 3 回それぞれでビームを打ち最初の手ごとに 3 つまで読み直す（2026-10-16 より前の既定）
- それでも、ルール・カード能力・評価関数や探索のコード・マリガンのモデル・貪欲法の重み（`DEFAULT_WEIGHTS`）を変えると相手の手も変わる。
  そこで相手どうしの決まった 14 試合の手順のハッシュ（指紋）を保存し、`cargo test`（`rust/engine/tests/yardstick.rs`）と記録の前に確かめる
- 指紋が変わったとき:
  - AI の変更が相手に漏れた（例: 評価関数のコードに新しい項を足し、既定で効くようにした）なら、相手では効かないように `reference_options` か重みを直して戻す
  - ルールやカード能力の修正などで戻せない・戻すべきでないなら、`VERSION` を上げて `FINGERPRINT` を書き直す。表は新しい節から始まる。
    違う版の行どうしは比べず、新しい版では今の既定と主な版を測り直す
- AI の一覧（`rust/engine/src/ai/registry.rs`）にも `yardstick` として載せてあり、web の「人間との比較」タブで相手に選べる（既定）

## 測り方

```sh
npm run yardstick -- --opts '{}' --games 1000                          # 今の既定の探索 AI（2000 試合、4 並列で数分）
npm run yardstick -- --opts '{}' --games 1000 --label "名前" --record  # この表に 1 行足す
npm run yardstick -- fingerprint                                       # 相手の指紋だけ出す
```

- `--opts` は `npm run compare` の設定と同じ形（`{}` が今の既定。`"valueNet"` 等も使える）
- 試合は compare と同じ組み方（7 デッキ、同じデッキの組で席とデッキを入れ替えて 2 試合ずつ、`--games 1000` で g0〜999 の 2000 試合）。
  相手は固定なので、同じ `--games`・`--start` なら行どうしは同じ試合（同じシード・同じデッキの組）で比べたことになる
- 2000 試合の標準誤差は 1 ポイントほど。差が 2〜3 ポイントより小さければ、同じ物差しでも結論は出さない（勝率の採否はこれまでどおり `npm run compare` で決める）
- 「コミット」の末尾の `+` は、コミットしていない変更がある状態で測ったもの
- デッキ別の列は、測った AI がそのデッキを使ったときの勝率（相手のデッキは 7 つすべてを含む）
- 「1 試合」は、並列で打った全体の時間を試合数で割ったもの（測った AI と相手の両方の思考を含む。4 並列の環境で測った値）

AI の改良を採用したら、その版を `--record` で足す。

物差し 1 の最初の 4 行は、2a0a0d7 のコードで既定の設定をその日付の既定に戻して測ったもの（その日付のコードそのものではない。
例えば 2026-10-16 に足した dominance は 4 行とも入っている）。学習した補正・相手のターンのビームサーチ・読み方の変更が、それぞれ物差しの上でどれだけ効いたかの目安。
