# 見落とし問題集（`npm run misses`）

人間が見て分かった AI のミスの局面を、合格の条件つきで集めたもの（`misses/*.json`、1 問 1 ファイル）。
今の AI にどの局面も 24 回ずつ解かせて、問ごとと全体の合格率（正解率）を出す。2026-11-10 から（審査の文書「AI の設計の審査と今後の方針」課題点 1「作るもの 2」）。

- **何のためか**: 勝率は 1 ポイントを見るのに数千試合かかり、まれな局面の直しは全体の勝率に埋もれる。問題集は「人間が分かったミスを今の AI がまだするか」を 1 分で見る。
  直したつもりの変更が狙いの局面を本当に直したか、別の変更で前に直った局面がまた崩れていないかを見る
- **勝率の代わりにはしない**: 正解率が上がっても、採用は今までどおり勝率で決める（CLAUDE.md「AI の実験記録」）。問題集は勝率で測る前のふるいと、崩れの見張り
- **シミュレータの中の試合だけ**: 局面は、このシミュレータの中の試合（自己対戦・人間とシミュレータの AI の対戦・手で作った局面）からだけ取る。
  問はこのコマンドと、ブラウザの「問題集」タブ（下の「問題集のページ」。公開サイトにも出す）で使う。ページで見られるのはリポジトリの問だけで、
  局面の編集・貼り付け・読み込みは付けない。実際の対戦の局面を入れて AI の手を聞く使い方はしない（CLAUDE.md「ソフト打ち」の禁止）

## コマンド

```sh
npm run misses -- run [--opts '<設定>'] [--trials 24] [--seed 1] [--label 名前] [--no-ledger] [--lines 2] [--only 問,…] [--out 結果.jsonl]
npm run misses -- add --id <問の名前> --pass '<合格の条件>' --title '…' --note '…' --source '…' [--agent search|rhino] [--no-run] [--force]
                      (--replay <記録> [--line N | --key subject/deck/g/seat] | --seed S --decks A,B [--agents search,search]
                       | --two-turn <局面の名前> | --state <局面.json>)
                      (--turn T | --step N) [--player 0|1]
npm run misses -- list
npm run misses -- show <問の名前>…
npm run misses -- check [--write-hand-logs] [--write-replays 問,…]
npm run misses -- cover [--opts '<設定>'] [--seeds 8] [--m 128] [--extra 4] [--wide 64] [--only 問,…] [--show]
npm run misses -- duel <問の名前> [--line '<名前>=<手の JSON の配列>']… [--m 512] [--base 1] [--no-stored] [--peek] [--show N [--dump <フォルダ>]]
```

本体は `rust/engine/src/runner/misses.rs`（`npm run svwb -- misses …` と同じ）。どれも `--dir` で別のフォルダの問を読む（既定は `misses/`）。

### run: 解かせる

各問の局面から、AI に手番の側のターンを終わりまで打たせ（相手の選択待ちが挟まれば相手は今の既定の探索 AI が選ぶ）、合格の条件を満たすかを見る。
これを AI の乱数だけを変えて `--trials` 回。局面の隠れた情報（相手の手札・山札、山札の順番、局面の乱数）は問のまま変えない。
AI は今までどおり、自分から見た決定化で考える（相手の手札を見ない）。

| 引数 | 既定 | 意味 |
| --- | --- | --- |
| `--opts '<設定>'` | `{}`（今の既定） | AI の設定。`compare` の A・B と同じ形。リノセウス用 AI（`"agent":"rhino"`）の問は `rhino-compare` の `--opts` と同じに読む |
| `--trials N` | 24 | 1 問を打つ回数。0 なら問題集と設定を読むだけ（夜のキューが書き間違いを見つけるのに使う） |
| `--seed S` | 1 | AI の乱数の元（回 r は `mix(S, r)` から、判断ごとに席・ターン・そのターンで何回目の判断かと合わせて作る。2026-11-10 から。`rust/engine/src/sim.rs` の `MatchRng`） |
| `--label 名前` | なし | 台帳の名前 |
| `--no-ledger` | なし | 台帳に書かない（動くかの確かめ等） |
| `--lines K` | 2 | 問ごとに、多かった打ち方を K 通りまで出す（○ が合格、× が不合格。0 で出さない） |
| `--only 問,…` | なし | その問だけ解く（台帳には書かない。問題集の正解率にならないため） |
| `--out 結果.jsonl` | なし | 問ごとの合格と、打ち方ごとの回数を書き出す |

出力は問ごとの合格（例 `0/24`）の表と打ち方、最後に全体の正解率。
**正解率** は問ごとの合格率の平均（今はどの問も同じ回数なので、合格した回数 ÷ 打った回数と同じ）。± は問ごとの合格率のぶれから出した標準誤差で、
問題集は決まったものとして見る（9 問 × 24 回で 1.3 ポイントほど、35 問で 1.0 ポイントほど）。回すたびに実験の台帳 `docs/ledger.jsonl` に 1 行足す（`kind` は `misses`。形は [ledger.md](ledger.md)）。

速さ: 9 問 × 24 回がクラウド環境（4 スレッド）で 26 秒（2026-11-10）、35 問 × 24 回で 47 秒（2026-11-12）。問を足すとその分かかる。

### add: 問を足す

局面を取り出して問のファイル（`misses/<問の名前>.json`）を書き、今の AI（既定の設定）に 24 回解かせた結果を出す（`--no-run` で出さない）。
書く前に読み直して確かめる。同じ名前があれば断る（書き直すなら `--force`）。

局面の元（どれか 1 つ）:

| 元 | 引数 | 中身 |
| --- | --- | --- |
| 記録した試合 | `--replay <ファイル>` | `npm run game -- --json` の出力、`compare --replays`・`rhino-compare --record` の 1 行、人間の対戦記録（`human-compare`。1 つの JSON でも JSON Lines でもよい）。JSON Lines は `--line N`（1 から）か `--key subject/deck/g/seat`（人間の記録）で選ぶ |
| 今の AI で打ち直す試合 | `--seed S --decks A,B [--agents a,b]` | `npm run game` と同じ試合を今の AI で打つ（AI を変えると流れが変わる。打ち直した行動の列は問に残す） |
| 手で作った局面 | `--two-turn <名前>` | `svwb two-turn show` の局面 |
| 局面のファイル | `--state <ファイル>` | サンドボックス（`npm run dev`）の書き出し（`{"format":"svwb-sandbox","state":…}`）か、状態の JSON そのもの |

局面の場所（記録した試合・打ち直す試合のとき）:

- `--turn T`: ターン T（`state.turn`。両者を通した番号）の最初の局面。ふつうはこれ
- `--step N`: N 個の行動を打った後の局面。見たい判断がターンの途中にあるとき（例: ウィリアムの後に錬金釜を置くか）

| 引数 | 意味 |
| --- | --- |
| `--id` | 問の名前（英数字と `-`・`_`）。ファイルの名前になる。`<クラス>-<中身>` の形にしている（例 `witch-od-hold`） |
| `--pass` | 合格の条件（下） |
| `--title` | ひとことの説明（何をすれば正解か）。`list` と `run` の表に出る |
| `--note` | 局面と、なぜそれが正解か（打ち比べの数字等） |
| `--source` | 出どころ（記録の節・ユーザーの指摘の日付） |
| `--agent` | 解かせる AI。`search`（今の既定の探索 AI。既定）か `rhino`（リノセウス用 AI。リノセウスエルフの問） |
| `--player` | 手番の側の確かめ（違えば断る） |

### list・show・check

- `list`: 問の一覧（AI・ターン・合格の条件・説明）と、問題集の指紋
- `show <問>…`: 問の中身（説明・出どころ・合格の条件・手番の側から見える局面・元の試合でその局面から打った手）
- `check`: 全部の問が読めるか（形・合格の条件のカードの名前・手番）と、出どころの記録から打ち直して同じ局面になるか。
  エンジンやカードの能力を直すと打ち直した局面が変わることがある（問の局面はそのまま使える。直した能力が局面に効くなら問を見直す）。
  `cargo test`（`rust/engine/src/runner/misses.rs` のテスト）でも、全部の問が読めて打ち直せることを確かめる
  `--write-hand-logs` は、打ち直した局面と手札の記録（`handLog`。[ai-notes/13](ai-notes/13-2026-11-13.md)「伏せた相手の手札のスペルブーストを決定化で見込む」）だけが違う問を、記録を入れた局面に書き直す（2026-11-13 に記録を足したときに使った）
  `--write-replays 問,…` は、名前を挙げた問を、打ち直した局面に書き直す（エンジンやカードを直して問の局面が変わったとき。差を見て、合格の条件がそのままでよいかを確かめてから使う）

### cover: 打ち比べ調査で拾える種類のミスか

各問を、候補の打ち比べ調査（[survey.md](survey.md)）と同じ作り方の候補と同じ打ち方にかけ、そのミスが調査で拾える種類かを見る（2026-11-11）。
問のミスを「読んでいるが評価が誤っている」「候補を広げれば入る」「候補にも作れない」に分けるのに使う。台帳には書かない（同じコマンドで同じ数字が出る）。

1. **候補**: 問の局面を、AI の乱数を `--seeds` 通り変えて今の既定の探索 AI に考えさせ（調査と同じ `SearchAgent::survey_plans`）、合格の条件を満たす並びがどこにあるかを数える。
   AI の選んだ並び・最後まで読んだ候補・AI が読み直す候補（上位 4 つと引く手。読み直しの途中で打ち切られたものも入る）・足した `--extra` 個まで（調査の候補はここまで）・足した `--wide` 個まで
2. **打ち比べ**: AI の選んだ並びが不合格で、合格の並びが調査の候補に入る問は、その 2 つの並びを調査と同じ打ち方で `--m` 回ずつ最後まで打ち、
   勝ちの数と勝率の差を出す。同じ回は、手番の側から見た決定化と AI の乱数が 2 つの並びで同じ。± は回ごとの差のばらつきから出した標準誤差

| 引数 | 既定 | 意味 |
| --- | --- | --- |
| `--opts '<設定>'` | `{}`（今の既定） | 候補を作る AI の設定（`run` の `--opts` と同じ形）。打ち比べの続きは、調査と同じく今の既定の AI が打つ。`planCandidates` が 2 以上の設定は扱えない（断る） |
| `--seeds N` | 8 | 候補を作る AI の乱数の数 |
| `--m N` | 128 | 打ち比べの回数（並びごと）。0 なら打ち比べない |
| `--extra N` | 4 | 調査が足す候補の数（調査の `--extra` と同じ） |
| `--wide N` | 64 | 「もっと足せば入るか」を見るために足す候補の数 |
| `--only 問,…` | なし | その問だけ |
| `--show` | なし | 乱数 0 の候補を全部出す（`読` は最後まで読んだ候補、`切` は読み直しの途中で打ち切られた候補、`足` は足した候補、`*` は AI の選んだ並び、○× は合格） |

| 表の出方 | 読み方（[survey.md](survey.md)「3 つの層」） |
| --- | --- |
| 最後まで読んだ候補に合格の並びがある | AI は合格の並びを相手のターンまで最後まで読んだうえで、別の並びを選んだ。評価の誤り（層 B。調査は拾える） |
| 読み直す候補にはあるが、最後まで読んだ候補には無い | AI は合格の並びを読み始め、引き直しを 3 通りほど読んだ所で大きく負けていると見て捨てた（`rescoreRace`）。これも評価の誤り（層 B。調査は `cut` の印の候補として拾える） |
| 足した `--extra` 個で入る | 読み直す候補を選ぶ段（最初の手ごとの最善と、ターン末の点数）で落ちている。調査は足した候補で拾える（層 B のうち「足した候補の分」） |
| `--wide` 個まで足しても無い | 探索の終点に合格の並びが無い。調査は拾えない（層 C か、リーサル探索の取りこぼし） |

- どの問も素の探索 AI（今の既定）で考える。調査がそうしているため（`compare` と同じく、リノセウスエルフも素の探索 AI が打つ）。
  `run` はリノセウスエルフの問をリノセウス用の AI に解かせるので、エルフの問の「AI の手が合格」は `run` の合格と合わない
- 打ち比べる並びは、AI の手が不合格だった最初の乱数のもの（1 問 1 組）。合格の並びは、調査の候補の中で最初のもの
- 打ち比べのシードは問の名前から作る（問を足しても、前からある問の数字は変わらない）。AI を変えると変わる
- 調査の「大きなミス」の線（一段目 32 回で 10 ポイント以上、二段目 96 回で 15 ポイント以上かつ標準誤差の 3 倍）は見ない。ここで出すのは 2 つの並びの差そのもの
- 128 回の差は標準誤差の 2 倍ほど動くことがある（2026-11-11 の `elf-af-t16` は +18.0 と 0.0）。大きさを言うときは `--m 512` で測る
- 速さ: 9 問・乱数 8・打ち比べ 128 回（6 問）がクラウド環境（4 スレッド）で 8〜10 分。`--m 512` は 40 分ほど。31 問・打ち比べ 64 回（28 問）は 19 分（2026-11-12）
- 2026-11-11 の結果は [ai-notes/12](ai-notes/12-2026-11-05.md)「見落とし問題集の問は打ち比べ調査で拾えるか」

### duel: 並びを指定して打ち比べる

問 1 つの局面で、名指しした並びどうしを最後まで打ち比べる（2026-11-12）。問の正解に「こちらの並びのほうが良いのでは」という指摘があったときに、その並びを測るのに使う。
`cover` は AI の候補の中の並びしか比べられないが、これは AI の候補に無い並び（式神を攻撃させずに残して終える等）も測れる。台帳には書かない（同じコマンドで同じ数字が出る）。

```sh
npm run misses -- duel <問の名前> [--line '<名前>=<手の JSON の配列>']… [--m 512] [--base 1] [--no-stored] [--peek] [--show N [--dump <フォルダ>]]
```

- 比べる並びは、書き添えてある調査の並び（`misses/lines/<問>.json` の「調査の AI の手」と「打ち比べで良い手」。`--no-stored` で外す）と、`--line` で足した並び。
  手の JSON は記録や `misses/lines/` と同じ形（`{"type":"play","iid":47}` 等。`iid` は問の局面のもの。問のファイルや `misses/lines/` で確かめる）
- **並びの後**: 並びが `{"type":"endTurn"}` で終わるなら、並びのとおりに打ってターンを終える（表の「ターンを終える」）。
  終わらないなら、調査や `cover` と同じく、並びの後の同じターンの続きを今の既定の AI が打つ（「AI が続ける」。AI は残った PP や攻撃を使うので、「何もせずに残す」並びはこの形では測れない）。
  どちらも、その後は両方の席を今の既定の AI が最後まで打つ
- 同じ回は、どの並びも同じ決定化（手番の側から見て矛盾しない局面）と同じ AI の乱数で打つ。差は `--base` 番（既定は 1 番）との、同じ回どうしの差の平均で、± はその標準誤差。
  シードは `cover` と同じく問の名前から作るので、書き添えた 2 つの並びの数字は、同じ並びを選んだ `cover --m` と同じ回数なら一致する。
  `--peek` は相手の手札を実際のままにする（山札の中身と順番、乱数は回ごとに作り直す。`survey recheck` と同じ）。
  `--peek` の数字は、相手の AI が受けない仕掛けを調べるためのもので、**問の正解を決めるのには使わない**（打つ側の知らない手札で正解が決まってしまう。`bishop-clear-g1689` を採点から外した理由。下の「相手の手札を見せて解く問」）
- 「合格」の列は、並びの分だけで問の合格の条件を見たもの（AI が続ける並びは、続きの手で変わりうる）
- 2 つ目の表は、回がいつ終わったか: このターンに勝ち・相手の次のターンに負け・自分の次のターンに勝ち・その後に勝ち・その後に負け。
  3 つ目の表は、自分の次のターンの最初の様子（そこまで続いた回の平均の、体力と場のフォロワーの数）。
  「次のターンのリーサルを狙う」「次の相手のターンは耐える」という狙いが、打ち継ぎで実際にそうなったかを見る
- `--show N` は、各並びの最初の N 回について、自分の次のターンの終わりまでの手と、ターンの変わり目の局面（相手の次のターンの最初は、その回に相手に配った手札も）を出す。
  `--dump <フォルダ>` は、その変わり目の局面を `<問>-L<番>-r<回>-t<1 か 2>.json` に書き出す（t1 が相手の次のターンの最初、t2 が自分の次のターンの最初。その回の決定化の局面で、相手の手札と山札は引き直したもの）。
  相手の受けを確かめるときは、書き出した局面を問の形のファイルにして（`--dir` の別のフォルダに置く）、相手の席から `duel` にかける
- 問の局面で打てない手がある並びは断る。決定化した局面で打てなくなった回は数えない（勝ちの分母が減り、2 つ目の表の「引き分け・打てない」に入る）
- **読むときの注意**: 測っているのは「その並びを打った後、今の既定の AI どうしが打ち継いだときの勝率」。
  - その並びを選ぶ人が続きで打つはずの手を今の AI が打てないなら、並びの本当の強さより低く出る
  - 相手の AI が受けない仕掛けは高く出る。今の AI は、伏せた相手の手札のスペルブーストを 0 として読む（[ai-notes.md](ai-notes.md)「これから」）ので、
    スペルウィッチがブーストのたまった鬼呼びの術などで次のターンに勝つ形を受けない。「自分の次のターンに勝ち」が多い並びは、`--show` で相手の受けを見る
    （2026-11-12 の `witch-storm-g1689`。[ai-notes/12](ai-notes/12-2026-11-05.md)「ユーザーが調査からの 26 問を確かめる」）
- 速さ: 5 つの並び × 512 回がクラウド環境（4 スレッド）で 2 分ほど（終盤の局面。試合の残りが長い局面はもっとかかる）
- 例:

  ```sh
  npm run misses -- duel witch-storm-g1689 --base 2 --show 4 \
    --line 'ご指摘の並び（式神は攻撃せずに終える）=[{"iid":47,"type":"play"},{"iid":76,"type":"play"},{"type":"endTurn"}]'
  ```

## 問のファイル

```json
{
  "v": 1,
  "id": "witch-od-hold",
  "title": "オーバーディメンションを温存し、次のターンにサタン → オーバーディメンション",
  "note": "手で作った局面（two-turn の witch-od-hold）。温存 59.4%、今打つ 37.5%…",
  "source": "docs/ai-notes/08-2026-10-25.md「2 ターン以上の計画が効きそうな局面を手で作って比べる」ユーザー案 3",
  "added": "2026-11-10",
  "agent": "search",
  "player": 0,
  "pass": {"mustNot":[{"play":"オーバーディメンション"}]},
  "origin": { "from": "two-turn", "scenario": "witch-od-hold", … },
  "state": { "phase": "main", "players": [ … ], … }
}
```

| 項目 | 中身 |
| --- | --- |
| `v` | 形の版（1） |
| `id` | 問の名前（ファイルの名前と同じ） |
| `title`・`note`・`source`・`added` | ひとことの説明・局面と正解の理由・出どころ・足した日 |
| `agent` | 解かせる AI（`search`・`rhino`） |
| `player` | 手番の側（局面の手番と同じでなければ読めない） |
| `pass` | 合格の条件 |
| `origin` | どこから取ったか。記録からの問は、シード・デッキ（カード ID の並び）・その局面までの行動の列（`check` が打ち直す）・元の試合でその局面から打った手（`played`） |
| `state` | 局面（状態の JSON。`src/engine/types.ts` の形。シードとターンではなく局面そのものを持つのは、AI を変えると試合の流れが変わるため） |

局面は状態の JSON なので、状態の形（`rust/engine/src/state_json.rs`）を変えたら問も直す（`check` と `npm test` が読めなくなって知らせる）。

## 合格の条件

`pass` は条件の組 1 つ（オブジェクト）か、組の配列（どれか 1 組を満たせば合格）。組の中は全部を満たせば合格。

| 項目 | 意味 |
| --- | --- |
| `must` | このターンに、この手を全部含む |
| `mustNot` | このターンに、この手をどれも含まない |
| `win` | このターンに勝つ（`true`） |
| `minHp` | ターンを終えたときの自分の体力がこれ以上（このターンに勝てば満たす） |

手の書き方（カードは名前。`*` はどれでも）:

| 手 | 例 | 意味 |
| --- | --- | --- |
| `play` | `{"play":"魔女の錬金釜"}` | プレイ |
| `attack` | `{"attack":"*","target":"相手のリーダー"}` | 攻撃（`target` は攻撃先。無ければどこでも。リーダーは `相手のリーダー`・`自分のリーダー`） |
| `evolve`・`superEvolve` | `{"evolve":"薫交の天宮・バックウッド"}` | 進化・超進化 |
| `act`・`fuse` | `{"act":"燐光の岩"}` | アクト・融合（融合はもとのカード） |
| `choose` | `{"choose":"燐光の岩","by":"虫の知らせ"}` | 対象等に選んだカード（`by` はその前に打ったプレイ・アクト・進化・超進化・融合・攻撃のカード。無ければどれでも） |
| `mode` | `{"mode":2,"by":"理光の証明"}` | 選んだ効果（1 から。画面の「n 番目の効果」） |
| `target` | `{"target":"楽朗の天宮・フィルドア"}` | 攻撃先か選んだカードに、そのカードを含む（除去の手段を問わない） |

カードの名前はカードのデータと照らし合わせ、書き間違いは読むときに断る。条件は「人間の手と同じ」より、正解の要（何をすれば・何をしなければよいか）を短く書く。
手の並びの順番は見ない。

## ユーザーにミスを指摘されたとき

1. 指摘の局面を記録から取り出し、今の AI でもミスするかを見る: `npm run misses -- add --id <名前> --pass '<条件>' --title … --note … --source … --replay <記録> --turn T`
   （`add` は最後に今の AI の合格を出す。指摘が人間の対戦の記録なら `--replay <記録.jsonl> --key …`、`npm run game` の試合なら `--json` の出力を `--replay` に）
2. 正解がはっきりしないとき（好みの分かれる手）は、打ち比べ（`branch_playout` の形や `two-turn`）で正解を確かめてから条件を書く。確かめられなければ足さない。
   古い記録から足すときは、同じ局面のいちばん新しい打ち比べを探して見る（AI が変わると、昔の AI の手は負けても今の AI の手は勝つことがある。エルフ T12 を外した理由）。
   正解は、打つ側の情報での打ち比べ（相手の伏せた手札は配り直す）で確かめる。相手の手札を実際のままにした打ち比べ（`duel --peek`）だけで勝つ手は、正解にしない（`bishop-clear-g1689` を外した理由）。
   直す実験の確かめに問を使うときは、先に上限を見る（直しが完全に効いたときの形、たとえば相手の手札を見せた AI（`peekOppHand`）で合格するか。しなければ、その直しでは合格しない）
3. 足した問のファイルを作業ブランチにコミットする（問題集の指紋が変わる。前の回の正解率とはそのまま比べない）
4. 直す実験をしたら、`npm run misses -- run --opts '<案>' --label <案>` で正解率を見て、勝率（compare）で確かめる

## 問題集のページ（ブラウザの「問題集」タブ）

問の局面をブラウザで見る画面（`src/ui/Misses.tsx`。2026-11-12 から。公開サイトにも出す）。`npm run dev` でも公開サイトでも同じものが出る。
問ごとの URL は `#misses/<問の名前>`（例 `https://wistery-k.github.io/Shadowverse-Wb-Sim/#misses/witch-mira-g1270`）。

- **一覧**: 問の名前・クラス・相手・手番の側の何ターン目か・正解（`title`）・解かせる AI・足した日
- **問**: 題・合格の条件（文と JSON）・説明（`note`）・局面のメモ（`two-turn` の問）・元の試合で打った手（記録から取った問）・出どころと、盤面（手番の側が下）。
  相手の手札は伏せ、ボタンで表にする（公開されたカードはいつも表。2026-11-12 のユーザーの選択）
- **盤面で進めて見る手**: 次の並びを 1 手ずつ進められる（←・→ のキーでも）。ターンを終えると、合格の条件を満たしたか（○ 合格・× 不合格）を出す
  - 打ち比べ調査から足した問: 調査の「AI の手」と「打ち比べで良い手」（`misses/lines/<問>.json`。下）。調査の並びは AI が考え直す所（ターンの途中で引く所）までなので、
    続きは「続きを今の AI に打たせる」か「ここでターン終了」で足す。調査で読んだターンの終わりまでの並び（AI から見た局面のもの）は横に文で出す
  - 「今の AI にこのターンを打たせる」: 問の局面から、問の AI（`agent`）にターンを打たせる（相手の選択待ちは今の既定の探索 AI）。押すたびに乱数を変える。
    AI は今までどおり自分から見た決定化で考える。`run` の回とは乱数の作り方が違うので、同じ並びになるとは限らない
  - 局面ごとに「AI の考え」（リプレイと同じ表）を出せる。「サンドボックスで開く」は開発サーバーだけ
- **合格の判定**: `src/misses/problems.ts` の `judgeTurn`。`rust/engine/src/runner/misses.rs`（`step_of`・`matches`・`passes`・`play_turn`）と同じ決まりで、
  どちらかを変えたら両方を直す。`npm test`（`tests/misses.test.ts`）で、全部の問が読めることと、調査の並びがターンの終わりまである問で良い手が合格・AI の手が不合格になることを確かめる
- **問のデータ**: ビルドに入れ、問題集のタブを開いたときに読み込む（別のチャンク）。問を足してコミットすれば、次のデプロイでページに出る

### 調査の並び（`misses/lines/<問>.json`）

打ち比べ調査から足した問には、調査で比べた 2 つの並びを別のファイルに書き添える（問のファイルに書くと問題集の指紋が変わるため）。
調査の出力から `npm run misses-lines -- <調査の出力.jsonl(.gz)>…` で書く（[commands.md](commands.md)「misses」）。調査から問を足したら、これも回してコミットする。

```json
{
  "v": 1,
  "id": "witch-mira-g1270",
  "source": "logs/night-20261111-2230/survey-1.jsonl.gz の試合 1270 の 7 手目",
  "lines": [
    { "kind": "ai", "label": "調査の AI の手", "steps": [{"iid":1,"type":"play"}], "text": ["魔女の錬金釜をプレイ"], "full": ["魔女の錬金釜をプレイ", "魔女の錬金釜の能力を使う"] },
    { "kind": "good", "label": "打ち比べで良い手", "steps": [{"iid":12,"type":"play"}], "text": ["アドラブルティーチャー・ミラをプレイ"], "full": ["アドラブルティーチャー・ミラをプレイ"] }
  ]
}
```

| 項目 | 中身 |
| --- | --- |
| `kind`・`label` | `ai`（AI の選んだ候補）か `good`（二段目で比べた候補）と、ページのボタンの名前 |
| `steps` | 調査の行の候補の `steps`（AI がその並びを選んだときに、考え直すまでに打つ手。問の局面から打てる） |
| `text`・`full` | `steps` の説明と、ビームの終局面までの並びの説明（調査の行の `text`・`full`） |

`bishop-clear-g1689`（`misses/peek/`）の並びは調査の出力に無いので、`duel` で打ち比べた 2 つの並び（今の AI の手と、全部取る手）を同じ形で手で書いた（`misses/peek/lines/`）。
Rust のランナー（`misses run` 等）は `misses/` のすぐ下の `*.json` だけを問として読むので、`misses/lines/` と `misses/peek/` は問として読まない（`misses/peek/` の問は `--dir misses/peek` で読む）。
ブラウザの問題集のページも `misses/*.json` と `misses/lines/*.json` だけを読むので、`misses/peek/` の問はページに出ない。
