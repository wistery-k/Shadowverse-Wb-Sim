## 棚卸し（2026-11-13）

スターターと同じカードを除いた 528 件（カード 459・トークン 31・クレスト 38）を、今の DSL（`src/engine/dsl.ts`）とエンジンで書けるかで分けた。
能力の文をすべて読み、足りない仕組みごとに正規表現でカードに印を付け、印の無いカードの文はスターターの能力の文の形と突き合わせて確かめた。見込みであり、確かになるのは能力を書いてテストを通したとき。

- 規模の分け方: **L** は新しい仕組みで、ルールの確認が要る。**M** は新しい誘発・効果・試合を通した記録で、状態（`src/engine/types.ts` と `rust/engine/src/state_json.rs`）に項目が増える。**S** は条件・対象・値・小さな効果の追加（DSL と Rust に数十行）
- 1 枚に複数の印が付くことがある。「これだけ足りない」は、その仕組みを足せば書けるようになるカードの数

### デッキで使うカードの見込み

84 デッキで使うカードは 181 種（515 種のうち）。上の棚卸しで数えると（関連するトークン・クレストの分も含めて）、今の DSL で書ける 101・S だけ足りない 31・M が要る 31・L が要る 18。
足りない仕組みは、L が 6 種類すべて、M が 17 種類のうち 14、S が 56 種類のうち 30。カードの数は全体の 3 分の 1 ほどだが、M と L の仕組みはほとんど全部が要る。

デッキの名前（サイトの呼び名）で分けた型ごとの、中心のカード（その型の半分以上のデッキに入るもの）と、それに要る仕組み:

## 段取りと見込み

見込みの時間は推測（スターターの実装にかかった時間の記録が手元に無いため）。カードの実装は PC の夜を使わない（ランダム自己対戦のスモークは Claude のクラウド環境で足りる）。

1. **変換と棚卸し**（この区切り。済み）
2. **ルールを先に書く**: ユーザーの答えを `docs/rules.md`「12」に出典付きで書く（質問 1〜21 と公式の用語説明は 2026-11-13 に済み。残りの 22・24〜28 は答え待ちで、それに関わる所は答えが出るまで作らない）
3. **エンジンの土台**（スレッド 1〜2 回）: 1 つのエンジンに両方のプールを入れ、試合を作るときにフォーマットで選ぶ案。
   能力の定義は今の `src/cards/abilities/` をスターター用に残し、新しいプールの分を別に置く（同じ ID の 81 件は共有。名前でカードを引く `id()` はプールごとにする）。
   フォーマットとデッキの検査・ランダム自己対戦のスモーク・不変条件の検査を新しいプールでも回す。スターターの試合の結果（ゴールデン）は変えない。
   **スターターのカードの番号は動かさない**: エンジンのカードの表（`npm run rust-data` が書く `cards` と `crests`。並びは `data/cards.json`・`data/crests.json` の順）の番号に、
   ゴールデン・物差し・今のモデルの読み込み・学び直し（`docs/STATE.md` の B）が依る。価値ネットの入力（14×248。PR #237 で 16×248）は、モデルの `vocab`（カード ID）から表の番号を引く。
   そこで、表の先頭はスターターの 241 枚とクレスト 7 件を今の順のまま置き、新しいプールにしか無いカード（490 件）とクレスト（38 件）はその後ろに足す（同じ ID の 81 件は先頭のものを共有する）。
   表全体を回す所（決定化の手札で働くカードの一覧、評価のカードごとの表）は、カードごとの値を作るだけなので、後ろに足してもスターターのカードの値は変わらない見込み。
   入れ替える前後で、ゴールデンと物差しの指紋が同じことを確かめる。今のモデルの入力の大きさ（`vocab` 248）は変えず、新しいプールの入力の形は段階 4 で決める
4. **S の仕組みと、今の DSL で書けるカード**（スレッド 6〜9 回）: 書けるカード 314 件と、S だけ足りない 98 件。カード単位の最小シナリオのテストを付ける
5. **M の仕組み**（スレッド 3〜5 回）: 17 種類、77 件。手札で働く能力・一時的なコスト・試合を通した記録・デッキのカードに働く効果など
6. **L の仕組み**（スレッド 3〜4 回。ルールの答えの後）: 奥義・直接召喚・連携・信仰・結晶・アクセラレート、39 件
7. **デッキとプロの試合の記録**: デッキは上の「プロのデッキ」で取り込んだ。試合の記録の形はユーザーに聞く。記録を取り込む仕組みは、実際の対戦の支援に当たらない形にし、作る前にユーザーに確かめる
8. **AI の作り直し**は段階 4（`docs/STATE.md`）。このプールの作業とは別に進める

3〜6 を合わせて、スレッド 13〜20 回ほどの見込み（推測）。

4〜6 は、プロのデッキで使うカード（181 種）から先に作れる。そうすれば、全部を作る前に、決まったデッキどうしの対戦を通せる。
順番の案: エンジンの土台 → L の要らないスペルW・アグロNi → 要る L の少ない型（ランプD・アミュレットB・コンボE など。ルールの答えの後）→ ハイランダーNm → 残りのカード。
カードの数は 3 分の 1 ほどだが、M・L の仕組みはほとんど全部が要るので、手間は全部の半分より多い見込み（推測）。
