# 評価に使うネットワーク（学習した補正）

探索 AI が局面に付ける点数は、手で作った評価（`eval.rs`）と、学習した補正（`data/value-net.json`）の和。
2026-10-31 からの既定の補正（relearn8、2026-11-01 から relearn9、2026-11-15 から B）は手で作った評価を 0 にして学んだもの（`--base zero`）で、点数は補正だけで付く（下の「評価の式」）。
この文書は、補正のネットワークの形・入力・出力・学習のしかた・使われ方をまとめる。
試したことの経緯と数字は [ai-notes.md](ai-notes.md) と [ai-notes/](ai-notes/) にある（文中の「」は ai-notes.md の節の索引から辿れる節の名前）。

2026-11-15 時点の既定の補正 **B**（2026-11-15 採用。入力に自分の山札に残るカード・相手のまだ見えていないカードを足して学び直したもの）について書く。既定の補正を学び直したら、この文書の数字（a・c・重みの数・経緯の表）も直す。

## 早見

| 項目 | 中身 |
| --- | --- |
| 何を当てるか | 局面から、視点のプレイヤーが勝つ確率。探索の点数には、手で作った評価に足す補正として入る |
| 形 | 全結合の 3 層。入力 4002 → 隠れ層 256（ReLU）→ 隠れ層 32（ReLU）→ 出力 1。重みとバイアスは合わせて 1,033,027 個 |
| 入力 | 視点のプレイヤーに見える情報だけ。カード・クレストごとの枚数など（16 種類 × 248）と数値 34 個。1 局面で 0 でない入力は平均 60 個ほど（B の自己対戦。足した 2 種類の分で、前の 35 個ほどから増えた） |
| 出力 | 勝つ確率のロジットへの補正 z。勝つ確率 = σ(a·S + c + z)、探索の点数には (c + z) / a を足す |
| 学習 | 両方の席がこの補正で打つ探索 AI の自己対戦から、TD(λ) で学ぶ。目標は λ 収益（最後は勝敗）、損失は交差エントロピー |
| ファイル | `data/value-net.json`（7.5 MB）。`npm run rust-data` で `rust/engine/data/ai-data.json` に書き出し、svwb と WASM に埋め込む |
| コード | 推論 `rust/engine/src/ai/valuenet.rs`、学習 `scripts/td-main.ts`・`scripts/valueNet.ts`、自己対戦 `rust/engine/src/runner/td.rs`、カードの属性 `scripts/cardAttrs.ts` |

## 評価の式

```
S          = 手で作った評価（eval.rs の evaluate_with、重みは src/ai/data.ts の SEARCH_WEIGHTS）
z          = ネットワークの出力（局面の入力 x から）
勝つ確率   = σ(a·S + c + z)
探索の点数 = S + (c + z) / a
```

- S の単位は「点」。相手のリーダーの体力 1 が 1 点、自分のリーダーの体力 1 が 0.7 点、手札 1 枚が 0.6 点など（`DEFAULT_WEIGHTS`・`SEARCH_WEIGHTS`）。
  2026-10-27 から、学び直しは `td train --base zero` で S を 0 にして学ぶ（ユーザー判断。S ありと同じ強さだった。docs/ai-notes.md「評価関数の手作りの項を外す」）。
  今の既定のモデル（B、2026-11-15 から。前の relearn8・relearn9 も同じ）はこの形で、`baseWeights` は全部 0。探索の点数は補正 (c + z) / a だけになる（a は学習で動かない）。読みの中の相手の予想などの方策は、探索 AI の既定の重みのまま
- **a**（今 0.0126）: 評価 1 点あたりのロジット。79 点でロジット 1、勝率 50% のあたりでは評価 1 点が勝率 0.3 ポイントほど。
  学習で決める（`--fitA 1`。下限 0.005）。`td init` の既定は 0.08 で、学び直すごとに下がってきた（2026-10-14 の最初の採用のころは 0.04 ほど）
- **c**（今 0.516）: ロジットの切片。出力の層のバイアス b2（今 0.516）と同じ勾配で動くので、2 つは実質 1 つの切片（合わせて 1.033）
- 補正 (c + z) / a は S と同じ「点」の単位になり、探索は S と足した値で手を比べる
- 試合が終わった局面では補正は 0（S の勝ち負けの点だけ）

### 補正の大きさ（測った値）

共有フォルダの自己対戦 `data/selfplay/royal-9/f0.jsonl.gz`（2000 試合、14 デッキ。介入の試合とランダムに打った局面を除く）の局面を、その日の既定の補正 s2ba で採点した（2026-10-25。relearn7〜relearn9 では測り直していない。relearn8 から S = 0 なので、S のばらつきの列は今の既定には当てはまらない）:

| 局面の種類 | 局面 | S のばらつき（標準偏差） | 補正の絶対値の平均 | 補正のばらつき（標準偏差） | ロジットでのばらつき a·S / c + z |
| --- | --- | --- | --- | --- | --- |
| ターン末 | 36,793 | 13.9 点 | 86.2 点 | 137.2 点 | 0.18 / 1.73 |
| 自分のターンの最初 | 35,086 | 17.2 点 | 86.4 点 | 131.8 点 | 0.22 / 1.66 |
| 想像の局面 | 68,959 | 19.6 点 | 77.4 点 | 111.2 点 | 0.25 / 1.40 |

- 局面どうしの違いのほとんどは補正が出している（ロジットでのばらつきは S の 7〜10 倍）。比較用の 7 デッキどうしの試合だけで数えても同じくらい
- ただし探索が手を選ぶのは、同じ局面から打てる並びどうしの点数の差。その差の中で S と補正がどう分かれるかは測っていない

## 形

```
入力 x（4002 個。ほとんど 0）
  ├ カード・クレストごとの入力  16 種類 × 248 = 3968
  └ 数値の入力                 34
        │  w1（4002 × 256）＋ b1
        ▼  ReLU
隠れ層 1（256）
        │  layers[0]（256 × 32）＋ b
        ▼  ReLU
隠れ層 2（32）
        │  w2（32）＋ b2
        ▼
z（1 つ）── (c + z) / a を S に足す
```

- 重みの数: w1 が 1,024,512（0 でないのは 690,108。4002 行のうち 0 でない行は 2772）、b1 が 256、2 つ目の層が 8,192 + 32、出力が 32 + 1、a と c
- 入力は疎なので、推論は 0 でない入力の行（256 個ずつ）だけを足す。1 局面の計算は 60 × 256 + 256 × 32 ≈ 2.4 万回の積和ほど（入力を足す前は 35 個で 1.7 万回ほど）。B の既定は、補正の計算 1 回が relearn9 の 1.55 倍・回数が 1.11 倍で、思考は 1.16〜1.18 倍だった（2026-11-15。B を採るときに見た 6〜8% より大きい。ai-notes/13「段階 4 の R1 の結果」）
- 推論（`ValueNet::eval`）は、隠れ層を 32 個ずつに分け、その分をレジスタに置いたまま 0 でない入力の行を順に足す（`add_rows`。x86_64 で AVX2 が使えれば 4 つずつ計算する。FMA は使わない）。
  要素ごとに足す順は「b1 に入力の行を 1 つずつ足す」形と同じなので、値はビットまで同じ（2026-11-15。補正 1 回 6.5 → 4.3 マイクロ秒・思考 0.87 倍で、上の遅くなった分はほぼ戻った。ai-notes の「補正の計算を速くする」）
- <a id="最後の隠れ層の使い回し"></a>**最後の隠れ層の使い回し**（2026-11-25）: 探索は同じ入力の局面を何度も採点する（読み直しの相手のビームなど。新しい既定の幅 8・深さ 8 で、採点の半分ほど）。
  そこで、足す行（添字と値。0 の行を除いたもの）が順番まで同じなら、前に計算した最後の隠れ層を使う（`valuenet.rs` の `MEMO`）。
  同じ補正に同じ行を同じ順で足すので、値はビットまで同じで、手は変わらない（テスト `hidden_memo_keeps_values_bitwise`）。
  - 表はスレッドごとに 2^14 個（WASM は 2^12 個）。1 つの位置に 1 つだけ入れ、外れたら上書きする。値は表の大きさによらない
  - 鍵は、補正の番号と足す行の 128 ビットのハッシュ。補正の番号は `ValueNet::new` が振る（番地は使わない。テストのように補正を作っては捨てると、
    同じ番地に別の補正が来る。テスト `hidden_memo_tells_nets_apart`）。別の行の鍵がぶつかる見込みは 1 回引くごとに 2^-128 ほどで、
    学習の自己対戦（6 万試合で 3×10^10 回ほど引く）を何度回しても起きない。
    行そのものを比べる形も作ったが、表が 1 スレッド 20 MB ほどになって読み書きが遅く、思考 0.97 倍にしかならなかった（128 ビットの鍵の表は 1 スレッド 5 MB ほどで 0.85 倍）
  - 入力を作る分（`encode`。補正の時間の 2 割ほど）は当たっても省けない
  - `svwb profile --no-memo` で使い回さずに打てる（値も試合も同じ。効きを同じビルドで測る）
- 最初の層は、行がカード（とその種類）ごとに分かれている。だからカードごとの重みを属性で埋める（下の `td attr`）ことができる
- モデルの JSON の入力の並び（`zones`・`scalars`）は、今のコードの並び（`ZONES`・`SCALARS`）の部分列であればよい。入力を足す前の古いモデルもそのまま読める
- 作れるが今の既定には無い形:
  - 隠れ層 1 つ（2026-10-19 まで。大きさ 32）。`layers` が無いモデル
  - 場のカードのネットワーク（`board`）。場のカード 1 枚ずつを小さなネットワーク（32・16）に通して自分の場・相手の場ごとに足し、最初の層の入力の末尾に入れる。
    6 万試合で学んでも上乗せが無く、採っていない（「場のフォロワーごとのネットワーク」・「3 回目」・「4 回目」）

## 入力

評価する側のプレイヤー p から見た局面を入れる。名前の `my` は p、`opp` は相手。

入れないもの: 相手の手札（公開されたもの以外）が何か、と山札の順番。探索は決定化した局面（相手の手札と山札を並べ直したもの）を評価するので、
見えない情報を入れると、でたらめに並べた手札に点数が振り回される（テスト `input_ignores_hidden_information`）。
並べ直しても変わらないもの（自分の山札に残るカードの集まり、相手のまだ見えていないカード（伏せた手札・山札・伏せた墓場）の集まり）は入れられる。
2026-11-13 に 14・15 として足した（案 B。2026-11-15 から今の既定のモデルにある。テスト `deck_inputs_do_not_change_with_determinize`）。

#### 相手の山札・手札の強化（2026-11-25、R7 の候補。今の既定のモデルには無い）

最後の 6 つは R7 の候補で足した（[ai-notes/15-2026-11-22.md](ai-notes/15-2026-11-22.md)「R7 の候補」）。R6 の測り（同じファイルの「補正は局面を読めているか」）で、
コンボE を相手にした側は相手の山札の強化の和で、アグロNi を相手にした側は相手の手札の強化の和で、値が実際の勝ちから 5〜11 ポイントずれていた。

決定化は相手の伏せた手札・山札の状態（`deck_kept`、伏せた手札のカードの攻撃力・体力の変化）を作り直す（強化は消える）ので、本当のカードの状態から入力を作ると、
本当の局面と決定化した局面で値が変わる（探索は決定化した局面だけを採点する。CLAUDE.md の方針 6）。そこで、相手にも分かる分をエンジンが数え（`PlayerState::pub_mods`。
ルールには効かず、ゴールデンの正規化した局面にも入れない。局面の JSON では `pubMods`）、入力はそこから作る:

- 山札（`pub_mods.deck_*`）: 山札を強化する能力（`buffDeck`。今はダストデイズのクレストの、山札のフォロワーを +1/+1）が働くたびに、1 枚あたりの量を足す。
  入力は「1 枚あたりの量の合計 × 山札のフォロワーの枚数の見込み」。見込みは、山札の枚数 × まだ見えていないカード（伏せた手札・山札・どれか分からない捨てたカード。`oppUnseen` と同じ）のうちフォロワーの割合。
  強化の後に山札に入ったカードや、強化を受けてから引いたカードの分はずれる（引いたカードの分は手札の入力にも入らない）
- 手札（`pub_mods.hand_*`）: 能力が伏せた手札のカードを強化したとき（誠実なる呪い屋・スージーの【進化時】。どのカードかは相手に分からないが、量は分かる）と、
  強化の付いた公開されていたカードが伏せた枠になったときに足す。伏せたカードを手札から出したとき・公開したとき（融合する側）に見えた強化のうち、山札の強化の量を越える分を引く（0 より下にしない）。
  捨てた・山札に戻したカードはどれか分からないので引かない。伏せた手札が無くなった後に伏せたカードが入ったら 0 から数え直す。入力は「公開された手札のフォロワーに付いた強化 ＋ この分（伏せた手札が無ければ 0）」
- どちらも決定化で並べ直しても変わらない（テスト `opp_buffs_and_max_hp_are_public_inputs`。手札の集計の決まりは `pub_mods_reveal_and_restart`、
  カードの場面は tests/pool-abilities.test.ts のスージーと tests/pool-abilities-combo-pirate.test.ts のダストデイズのクレスト）

### 局面の種類

同じ局面でも、どの時点の局面かで入力の `after`・`imagined` が変わる（`ValuePhase`）。

| 種類 | `after` | `imagined` | どこで使うか |
| --- | --- | --- | --- |
| ターン末（`End`） | 0 | 0 | 探索のターン末の採点。ターン終了時の処理を進めた後の局面 |
| 自分のターンの最初（`After`） | 1 | 0 | 学習だけ（λ 収益を計算するときの「次の局面」）。探索は使わない |
| 想像の局面（`Imagined`） | 1 | 1 | 探索の読み直し。相手のターンを読んだ後の、自分の次のターンの最初 |

`imagined` は 2026-10-22 に足した。読みの中の相手は本物より甘く、読んだ後の局面を平均 6〜7 ポイント楽観していたので、そのずれを学ばせるため（「読みの中の相手のずれを学習で直す・資源の介入」）。

## 使われ方

### 探索 AI（`search`）

1. 自分のターン: ターン末までのビームサーチ（幅 512・深さ 16）の各終局面を、ターン終了時の処理を進めてから S + (c + z) / a（ターン末）で採点する
2. 読み直し: ターン末の点数の上位 4 つの最初の手について、相手の手札を 12 通り引き直し、相手のターンを幅 8・深さ 8（2026-10-31 から。前は幅 16）のビームサーチで打った後の局面を
   S + (c + z) / a（想像の局面）で採点して平均する。選ぶ点数は、これとターン末の点数を半分ずつ混ぜたもの（`rescoreMix` 0.5）
3. 読みの中の相手は補正を使わず、手で作った評価だけで打つ（`opponentSearch.extraEval` が false。足しても効かなかった。「棋譜の指摘: バックウッドかフェアリーか」）

探索の全体の形は [ai-notes.md](ai-notes.md)「今の AI」。

### ほかの所

- リノセウス用 AI（`rhino`）: 同じ補正に、リノセウスの打点の項（`RHINO_POTENTIAL`）を足して使う
- マリガン: 既定（`mulligan: "turn1"`・`mulliganTurns` 3、2026-10-26 から）は、返し方ごとに引き直した後、3 ターン目の自分のターンの終わりまで貪欲法で打ち進めた局面を
  S + 補正（ターン末）で比べる（`mulliganTurns` 0 なら 1 ターン目の最初の局面を S + 補正（ターンの最初）で）。`mulligan: "sample"` は引き直した直後の局面を S + 補正（ターン末）で比べる。
  手札の形のモデル（`mulligan: "model"`、2026-10-26 より前の既定）は補正を使わない
- 補正を使わない AI: `search-classic`、物差し（`yardstick`）、貪欲法
- 強い相手の物差しは、2026-10-22 の既定（s2b）の写し `rust/engine/yardstick/strong-1-net.json` を使う。既定を学び直しても動かない（[yardstick.md](yardstick.md)）

  書き出した後に元のファイルが変わっていれば、ビルドは「埋め込むデータが古くなっています」で止まる（[rust/README.md](../rust/README.md)）。WASM は補正の分だけ大きい（8.3 MB）

## 学習

### 流れ

1. 自己対戦: 今の既定の補正を入れた探索 AI どうしで打つ（`svwb td selfplay`、6 万試合）
2. 学習: 今の補正から続けて学ぶ（`npm run td -- train`）
3. 後の処理: `td prune` → `td attr`
4. 判定: 今の既定と打ち比べる。採用なら `data/value-net.json` を置き換え、次の回はその補正で自己対戦を作る（学んだ評価で打って学び直す閉じた輪）

ここ数回の手順（[ai-notes.md](ai-notes.md)「今の AI」の「補正を学び直すときの手順」と同じ）:

```sh
# 自己対戦（ユーザーの PC で 3000 試合ずつ 20 回、28 並列で 4 時間ほど）
svwb td selfplay --model data/value-net.json --games 3000 --start <g> --eps 0.1 --opp beam --sampling default --iv 3 --ivZone both --imagined 2 --out d<i>.jsonl
# 学習（6 万試合で 45 分ほどの見込み。2026-10-30 に速くする前は 1 時間ほど）
npm run td -- train --model data/value-net.json --data d0.jsonl,...,d19.jsonl --out m.json --epochs 3 --lr 0.0003 --l2 0.001 --best 1 --bestOn end,imagined
# 後の処理
npm run td -- prune --model m.json --data d0.jsonl,...,d19.jsonl --out mp.json
npm run td -- attr --model mp.json --out mpa.json --keepA 0
```

### 自己対戦のデータ

- 両方の席が、学ぶ前の補正を入れた探索 AI（既定の読み方。`--sampling default --opp beam`）。比較用の 7 デッキの全 49 組を順に回す（`--decks` で変えられる）
- 各プレイヤーについて、自分のターンの最初（`"ph": 1`）、ターン末（`"ph": 0`）、想像の局面（`"ph": 2`。そのターンに選んだ並びの読み直しで作った局面から 2 つ、`--imagined 2`）を書く。
  各局面に S（`"s"`）、入力の添字と値（`"x"`・`"v"`）、場のカードの属性（`"b"`）がある
- 10% の確率で、自分のターンの最初の手をランダムに打つ（`--eps 0.1`）。その局面（`"ex"`）は学ばず、1 つ前の局面の目標もそこで切る
- 介入（`--iv 3 --ivZone both`）: 各試合で 1 つ、どちらかのプレイヤーの 3〜8 ターン目の自分のターンの最初から、手札か場のカードを 1 枚消した局面を 3 つ作り、
  そこから最後まで打った試合も書く。カードの価値を「その局面の後に勝ったか」の相関ではなく、消した結果から学ばせる（「介入データを TD 学習に混ぜる」・「場のカードを消す介入を混ぜる」）
- `"x"` は自己対戦に使ったモデルの入力の並びで書き、ファイルの 1 行目にその並び（`{"tdLayout":{"vocab":[…],"zones":[…],"scalars":[…]}}`）を書く（2026-11-13 から）。
  `td train`・`prune` 等は、学ぶモデルの並びに読み替える（モデルに無い入力は捨てる）。だから入力を足したモデル（`td extend`）で作った自己対戦 1 つから、
  入力あり（足したモデルから）と入力なし（足す前のモデルから、または `--dropInputs`）の両方を学べる。並びの行が無い前のファイルは、学ぶモデルの並びとみなす。
  `"b"` は入力に直す前の値なので、場のカードのネットワークは作り直さずに学べる
- 自己対戦のファイルは gzip したまま（`.gz`）読める
- `--excludeDecks <デッキ名>`・`--onlyDecks <デッキ名>`（train・prune）: そのデッキの絡む試合を学ばない・そのデッキの絡む試合だけを学ぶ（見ていないデッキでの落ち方と学び足しを測る、案 E）
- 量: 6 万試合で、ターン末と自分のターンの最初が 540 万局面ほど。想像の局面を入れると、学習に読む局面は 2 倍ほどになる

### 目標

プレイヤーごとに、局面は「ターンの最初 → ターン末 → 次のターンの最初 → …」と並ぶ（想像の局面は、直前のターン末に付く）。

```
G_t = (1 − λ) · V_{t+1} + λ · G_{t+1}     （λ = 0.7）
最後の局面の G = 勝敗（勝ち 1・負け 0）
V   = 今学んでいるモデルの予測 σ(a·S + c + z)。エポックの最初に全局面で計算し直す
```

- 次の局面がランダムに打った局面なら、G_t = V_{t+1}（そこで切る）
- `--cutOpp 1`（2026-11-25、R7 の候補。既定 0）なら、次の相手のターンの最初の手がランダムな手だったターン末（自己対戦の `"oe"`。`td selfplay --lostLabel 1` で書く）も、
  G_t = V_t（その局面の値で切る。その局面は学ばない。その前の局面の G もそこで止まる）。自分のランダムな手だけを切ると、値は「自分はランダムに打たず、相手だけ 1 割でランダムに打つ世界」の
  勝率になり、両方の席で高すぎる（R6 の測り。[ai-notes/15-2026-11-22.md](ai-notes/15-2026-11-22.md)「補正は局面を読めているか」の、学びの自己対戦のランダムな手）。
  相手のターンの最初の局面は相手の席の並びにあり、その値は相手から見た値なので、切るのは自分の席のターン末で止める形にした
- `--epochOut m-e{e}.json`（2026-11-25、Rust 版の `svwb td train`）なら、`--out` とは別に、エポックごとの重みも書き出す（`{e}` はエポックの番号）。
  `--best 1` の選び方（確かめ用の局面の実際の勝敗との交差エントロピー）は相手が 1 割ランダムに打つ世界の勝敗で選ぶので、値をわざと下げる `--cutOpp 1` の版では狙いに逆らう。
  R7 の候補では、切る版は対照が選んだのと同じエポックの版を使う（`night/r7-1.txt` の先頭）。学びの報告の end には、確かめ用のターン末の予測の平均と勝ちの割合も出す（楽観の大きさ）
  （2026-11-26 の訂正: 確かめ用の勝敗は両方の席が 1 割ランダムに打つ世界のもので、`--cutOpp 1` はそれに近づく側なので、`--best` は切る版に不利でなく有利だった。そろえる決まりは比べをきれいにするので残す）。
  確かめ用のターン末のおよそ 6 割は、途中から始まる介入の試合のもの（r7-1）なので、この予測の平均・勝ちの割合はふつうの試合の序盤の楽観より小さく出る
- `--byTurn 1`（2026-11-26、Rust 版の `svwb td train`。調べだけで、学習は変えない）なら、学習前と各エポックの報告の後に、確かめ用のターン末（ランダムに打った局面と、
  介入して打った試合を除く）をその席の何ターン目か（1〜2・3〜4・5〜6・7〜8・9 以上）に分け、予測の平均・自分のランダムな手の前だけで切る λ 収益（`--cutOpp 0` の目標）・
  相手のランダムな手の前でも切る λ 収益（`--cutOpp 1` の目標。"oe" のある自己対戦だけ）・勝ちの割合を並べる。目標はその報告の値で作る（次のエポックの目標）。
  `--epochs 0 --model <学んだ版>` で、その版から作る目標を見られる。r7-1 では、切った目標も序盤ほど楽観したまま（出発の R6 から作ると 1〜2 ターン目で +5.3 ポイント、9 ターン目以降 +0.7）で、
  エポックごとに序盤へ直りが進んだ（docs/ai-notes/15-2026-11-22.md「切ったところの値も楽観していないか」）
- `--searchTarget m`（既定 0）なら、V_{t+1} の代わりに (1 − m)·V_{t+1} + m·Q_{t+1} を使う。Q はそのターンに探索が選んだ並びの値を勝つ確率にしたもの
  （自己対戦の `"qe"`・`"qr"`。`td selfplay --searchValue 1` で書く。(1 − `--searchMix`)·相手のターンを読んだ後の平均 + `--searchMix`·ターン末）で、
  ターン末の局面はそのターンの、ターンの最初の局面は同じターンのターン末の局面の値。自己対戦のモデルのもので、エポックごとに計算し直さない
  （ai-notes.md「補正の学習の目標に探索の値を使う」）
- 想像の局面の目標は、同じターンのターン末の局面と同じ（本物の次の自分のターンの最初からの λ 収益）。
  読みの中の局面と、その後に本物で起きたことを並べて学ぶことになる

### 損失と最適化

- 損失: 予測 σ(a·S + c + z) と目標 G の交差エントロピー。局面ごとの重みは、介入の試合が `--ivWeight`、想像の局面が `--imaginedWeight`（どちらも既定 1）
- 学ぶもの: 全部の重み・バイアスと、c・a
- Adam（β1 0.9・β2 0.999）、ミニバッチ 128 局面、学習率 0.0003（`--lr`）、3 エポック（`--epochs`）。
  重みの減衰 0.001（`--l2`。重みから直接引く形で、バイアス・c・a は減衰させない）
  読んだ局面に一度も出ない入力の行は更新しない（勾配が常に 0 で、`td prune` で 0 にする行。2026-10-30 から減衰もかけない。ai-notes.md「td train を速くする」）
- 確かめ用: 試合番号から決めた 1 割の試合を学ばずに取っておき、エポックごとに勝敗の交差エントロピー・AUC を出す。
  `--best 1 --bestOn end,imagined` で、ターン末と想像の局面（探索が点数に使う 2 つ）の交差エントロピーが一番小さいエポック（学習前も含む）の重みを書き出す
- 一から学ばず、今の補正から続けて学ぶ。同じデータなら続けて学んだ版のほうが少し強く、一から学ぶ 256・32 は 3000〜6000 試合ではデータが足りず弱かった
  （「大きなネットワークで一から学び直す」・「自己対戦を増やして補正を学び直す」）

### 学んだ後の処理

- `td prune`: 学習データに一度も現れなかった入力の行を 0 にする。学ばれずに初期値の乱数のまま残っているので、そのカードを使うデッキで補正がでたらめに動かないようにする
- `td attr --keepA 0`（リッジ回帰の罰 3）: カードの行を、カードの属性（`scripts/cardAttrs.ts`、今のカードで 156 個。種類・クラス・コスト・攻撃力・体力・キーワード・タイプ・
  能力のきっかけ × 効果のプリミティブ等。テキストは使わない）の線形和で当てはめ、学んでいない（0 の）行をその当てはめで埋める。
  初見のカードも、属性からそれらしい値で見られる（新しいデッキで +4.9 ポイント。「カードの重みを属性とカードごとの残りに分ける」）。
  最初の層は線形なので、埋めた行を w1 に書き込むだけで、推論は変わらない

### 判定

今の既定と `npm run compare`（同じシードで席とデッキを入れ替え、組の 2 試合を鏡にする）で 6000 試合ほど打ち、物差し 2 つ（`npm run yardstick`）とリノセウス用 AI も見る。
予測の精度（交差エントロピー・AUC）が良くなっても、勝率で確かめるまで採らない（予測が良くて勝率が下がった例が何度もある）。採ったらゴールデンテストを保存し直す。
決め方は [ai-notes.md](ai-notes.md)「判断のしかた」。

### リーサルの出力（実験）

2026-11-21 から。既定の補正・ブラウザの補正は持たない。次の学び直しの夜に、同じ自己対戦から 3 つ学んで比べる（ユーザー決定 2026-11-21。
[ai-notes/14](ai-notes/14-2026-11-16.md)「死ぬ確率と生き延びたときの勝率で候補を選んだら」の終わり）:

| 名前 | 形 | 損失 | 探索が使う値 |
| --- | --- | --- | --- |
| C | 今のまま（出力 1 つ） | 勝つ確率 σ(a·S + c + z) と λ 収益 G の交差エントロピー | (c + z) / a |
| X（`--lethalHead aux`） | 最後の隠れ層から、次の相手のターンに負ける確率 q = σ(bp + wp·h) も出す | C の損失 ＋ `--lethalWeight` × q と印の交差エントロピー | C と同じ（q は使わない。学び方だけが違う） |
| Z（`--lethalHead survival`） | 勝つ確率を (1 − q) × σ(c + z) にする（σ(c + z) は生き延びたときの勝率） | その勝つ確率と G の交差エントロピー ＋ `--lethalWeight` × q と印の交差エントロピー | logit((1 − q) × σ(c + z)) / a。出発点の評価は 0（`--base zero`）だけ |

- 印（`td train --lethalTarget lost`、既定。ユーザー決定 2026-11-21）: 自己対戦の各ターン末で、次の相手のターン（その初めと終わりの処理も含む）に実際に負けたか
  （`svwb td selfplay --lostLabel 1` が `"ln": 1|0` を書く。試合の結果から書くだけで、打つ手・試合・速さは変わらない。`kifu values` の `lostNext` と同じ印）。
  Z の (1 − q) × s は、q を次の相手のターンに負ける確率、s を生き延びたときの勝率にすると、勝つ確率の分解としてそのまま合う。
  `--eps` のランダムな手はターンの最初の 1 手だけで、リーサルを確かめる前に決まる（相手はリーサルがあっても最初の手をランダムに打つ）。
  そこで、次の相手のターンの最初の手がランダムな手だった局面（`"oe": 1`。ターン末の 1 割ほど）は、出力の学びから除く（ランダムに打つかは局面によらず決まるので、除いても残りは偏らない）。
  介入の試合（`--iv`・`--ivRes`）は、変えた局面から打った試合の結果なので、同じように付ける
- 比べる用の印（`--lethalTarget search`）: 本当の局面のままターンを終え、相手の番の初めにリーサル探索（`finds_lethal`。打ち手の設定のリーサル探索の項目で探す）が相手の勝てる並びを見つけるか
  （`svwb td selfplay --lethalLabel 1` が `"ol": 1|0` を書く。打つ手・試合は変わらないが、自己対戦が 15% 遅くなる）。#292 の `kifu values --true-lethal 1` の `oppLethal` と同じ印。
  `lostNext` との食い違い（探索が見つけても相手の AI が打たない・ターン終了時の効果や引く手で勝つ）は [ai-notes/14](ai-notes/14-2026-11-16.md)「リーサルの出力を足して学ぶ準備」
- 出力の無いモデルに付けるときは wp を 0、bp を学習側の局面の印の割合のロジットで始める。Z は最初、勝つ確率がその割合だけ下がった所から学ぶ
- `td train` は確かめ用のターン末で、リーサルの出力の交差エントロピー（割合だけで当てたときと並べて）と AUC（勝つ確率の低さの AUC と並べて）も出す。`--best` の判定は今までどおり勝つ確率の交差エントロピー
- モデルのファイルには `"lethalHead": {"w": [...], "b": ...}` と、Z なら `"winForm": "survival"` を足す（無ければ今までの形）。推論は Rust（`ValueNet::eval`、`lethal_prob`）。
  TypeScript の計算（`npm run td -- train`・`check`・`eval` 等）はこの形を扱わずエラーにし、`td extend`・`td attr` は w1 だけを変えてそのまま書き出す
- 出力の無いモデルの学習は今までと同じ計算（TypeScript 版と同じ重み。`fixtures_match_typescript`）。印のあるデータでも、出力を付けなければ同じモデルを書く
- `svwb kifu values --opts '{"valueNet":"<出力のあるモデル>"}'` は、ターン末ごとにリーサルの出力の確率（`netLethal`、%）も書く。比べ方は [ai-notes/14](ai-notes/14-2026-11-16.md)「リーサルの出力を足して学ぶ準備」

### 勝ちの出力・読みの出力（R6 の候補）

2026-11-22 から。R5（Z）にさらに 2 つの出力を足す案で、R6 の候補の夜（`night/r6-heads-1.txt`）に同じ自己対戦から B・I・W・V・F・A の 6 つを学び、
取り置きのデータで 1 つを選んで R5 と比べる（ユーザー決定 2026-11-22。計画と選ぶ決まりはジョブのファイルの先頭）。どちらもリーサルの出力と一緒にだけ学ぶ。

| 名前 | 形 | 損失に足すもの | 探索が使う値 |
| --- | --- | --- | --- |
| W（`--winHead form`） | 最後の隠れ層から、自分の次のターンに勝つ確率 w = σ(bw + ww·h)（次の相手のターンを生き延びたとき）も出し、勝つ確率を (1 − q) × (w + (1 − w) × σ(c + z)) にする | `--winWeight` × w と印の交差エントロピー | logit((1 − q) × (w + (1 − w) × σ(c + z))) / a（`"winForm": "survivalWin"`） |
| V（`--winHead aux`） | w を補助の出力として出す（勝つ確率の形は Z のまま） | 同じ | Z と同じ（w は使わない） |
| F（`--readHead aux`） | 読みの中の相手に負けた割合を当てる r = σ(br + wr·h) を補助の出力として出す | `--readWeight` × r と印（0〜1 の割合のまま）の交差エントロピー | Z と同じ（r は使わない） |

- w の印（`svwb td selfplay --wonLabel 1`）: 各ターン末で、自分の次のターン（ターン末の 2 つ後のターン。その初めと終わりの処理も含む）に勝ったか（`"wn": 1|0`。`kifu values` の `wonNext` と同じ）と、
  そのターンの最初の手が `--eps` のランダムな手だったか（`"we": 1|0`）。w を学ぶのは、次の相手のターンを生き延び（`"ln": 0`。`--lostLabel 1` も要る）、自分の次のターンまで
  試合が続いた（次の局面が自分のターンの最初の局面か、`"wn": 1`）ターン末だけ。`"we": 1` の局面（相手はリーサルがあっても最初の手をランダムに打つのと同じ理由）と、
  試合が相手のターンで相手の負けに終わった局面（山札切れなど）は学ばない
- r の印（`--readLabel 1`）: 探索が読んだターン末で、そのターンの最後の探索が選んだ並びの読み（相手の手札の引き直しごとに相手のターンまで読んだ局面。`--searchValue` の `"qr"` と同じもの）のうち、
  読みの中の相手が勝った割合（`"rf"`）と読みの回数（`"rn"`）。読みの無いターン末（リーサルを打った等）には書かない。`--readMin n` なら rn が n 以上の局面だけ学ぶ（既定 1）
- どの印も試合の結果と探索がすでに作った読みを書くだけで、打つ手・試合・速さは変わらない（テスト `won_and_read_labels_on_turn_ends_without_changing_games`）
- 付けるときは重みを 0、偏りを学習側の印の割合（r は印の平均）のロジットで始める。ただし W（`form`）の w は 0.1% で始め、学ぶ前の勝つ確率を R5 とほぼ同じにする（多くても (1 − q)(1 − s) × 0.1% 上がるだけ。テスト `win_and_read_heads_train`）。印の割合（1 割ほど）で始めると、R5 の s がすでに次のターンに勝つ分も含んでいるので二重に数え、取り置きのデータで勝つ確率が平均 4.18 ポイント（多いところで 9.58）上がった所から学んでいた（クラウドの小さな通し）
- `td train` は確かめ用のターン末で、w の交差エントロピー（割合だけと並べて）と AUC（勝つ確率の AUC と並べて）、r の交差エントロピー（平均だけと並べて）も出す
- モデルのファイルには `"winHead"`・`"readHead"`（`{"w": [...], "b": ...}`）と、W なら `"winForm": "survivalWin"` を足す。ページの補正には w だけを詰め（指紋にも入る）、
  r は詰めない（`scripts/pack-nets.ts`。手を選ぶのに使わない）。`svwb kifu values` は `netWin`・`netRead`（%）も書く
- 出力を付けなければ、印のあるデータでも Z と同じモデルを書く（テスト `win_and_read_heads_train`）。勾配は数値微分と比べた（`lethal_gradients_match_finite_differences`）

## 試して採らなかったこと

- 勝敗から直接学ぶ（ロジスティック回帰、学んだ評価で打ち直さない）: 基準の重みに勝ち越せない（「評価関数の学習」）
- 大きいモデル（256・32）を一から 3000〜6000 試合で学ぶ: データが足りず弱い。大きいモデルは 3 万〜6 万試合で初めて伸びた（「大きなネットワークで一から学び直す」・「今のモデルを広げて学習を続ける」）
- 場のフォロワーごとのネットワーク: 6 万試合でも上乗せなし（「場のフォロワーごとのネットワーク」・「3 回目」・「4 回目」）
- 同じ局面からの手の比べ合い（打ち比べの勝率）を学ぶ: 伸びない（「同じ局面からの手の比べ合いを学ぶ」）
- 資源（EP・SEP・リーダーの体力・最大PP）を ±1 した介入: 伸びない（「読みの中の相手のずれを学習で直す・資源の介入」）
- 12 万試合で学ぶ・学習率をさらに下げる: 伸びない（「4 回目」・「自己対戦を作らずに学び方を詰める」）
- カードの属性の重みを一緒に学ぶ（`train --attr 1`）: 知っているカードの行が速く動きすぎて悪くなる（「カードの重みを属性とカードごとの残りに分ける」）
- 読みの中の相手にも補正を足す: 効かない（「棋譜の指摘: バックウッドかフェアリーか」）
- λ 収益の次の局面の予測に探索の値を混ぜる（`td train --searchTarget`）: 半分でも全部でも勝率は変わらない（「補正の学習の目標に探索の値を使う」）
- 推論で、山札の中身の入力（`myDeckCards`・`oppUnseen`）の分を先に足して使い回す: 補正 1 回がさらに 0.84 倍だが思考は 3% ほどで、足す順が変わるので試合の 3 分の 1 が変わる（「補正の計算を速くする」）

## 分かっている癖

- 手札の枚数を高く見る・最後の 1 枚を出すのを嫌う傾向がある（AFネメシスで手札を残す、手札がジェノだけの局面でジェノを出さない）
- 最大PP と EP の価値を、介入で測った値より低く見ている（最大PP は半分以下、EP は 6 割ほど）
- 自己対戦に無い局面は学べない。例えば、リーアムのために EP を残す局面が自己対戦にほとんど無いので、リーアムが手札にあっても EP を重く見ない（「補正はカードごとの EP の価値を学んでいるか」）
- 次のターンにリノセウスで倒しきる形で、とどめの道具（手札の森の神秘・招集、場の燐光の岩）を持つほど点を下げる
- 入力はカードの枚数が中心で、場にいる間に働く能力やエンハンスで育ったカードを見分けにくい

詳しくは [ai-notes.md](ai-notes.md)「分かったこと」の「学習した補正（TD 学習）」と「分かっている弱点・未着手の候補」。
