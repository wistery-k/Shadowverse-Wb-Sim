## R6 の候補: 勝ちの出力・読みの出力・入力 7 つ（2026-11-22、計画と実装・クラウド環境の小さな通し。ユーザー決定）

- **きっかけ:** 次の学び直しに乗せる候補が 3 つ残っていた（[14](14-2026-11-16.md)「Z と C の打ち方の比べ」の審査の確かめの後）。自分の次のターンに勝つ確率の出力（`wonNext` を印に、Z の q と同じく最後の隠れ層から）、
  読みの中の相手に負けた割合を教師にする出力、リーサルの見込みに足りない公開の入力（アミュレットのカウント・クレスト）。ユーザー「今持っている案を３つとも試してもそこまで手間は増えないという理解なのですがどうでしょうか」。
  審査のスレッドで計画を詰め、ユーザーが実装を始めると決めた（2026-11-22）
- **決めたこと（回す前。`night/r6-heads-1.txt` の先頭）:**
  - 自己対戦は 1 回だけ（6 万試合、打ち方は R5、見込みは R4 のまま）。同じデータから 6 つを学ぶ: B（入力 7 つを外し、R5 と同じ形で学び直す。案の効きは B との差で見る）・I（入力 7 つ）・
    W（勝つ確率 = (1 − q) × (w + (1 − w) × s)）・V（w を補助の出力として学ぶ）・F（読みの中の相手に負けた割合 r を補助の出力として学ぶ）・A（入力 7 つ ＋ W の形 ＋ r）
  - 翌朝、取り置きのデータ（Z 対 C の compare、夜のキュー `lethal-heads-2` の g0〜5999 の A の席）で 1 つを選ぶ。各版の勝敗の交差エントロピーの B との差 Δ と、試合ごとのブートストラップの SE を出し、
    Δ + 2 SE < 0 で q の AUC が B の AUC − 2 SE 以上の版を残し、交差エントロピーがいちばん小さいものを選ぶ。残らなければ B
  - 2 晩目（`night/r6-heads-2.txt`）で選んだ版 対 R5 を 2 万試合。差 − 2 SE > 0 なら採否をユーザーに出す。越えなければ R5 のまま。
    この比べで勝っても、案が効いたのか学び直し 1 回分なのかは勝率では分かれない（ユーザー了承済み）。B のモデルは残し、後から「選んだ版 対 B」を回せるようにする
  - 試合数: 学び直し 1 回の伸びは R3 対 R2 +1.56・R4 対 R3 +2.13・C 対 R4 +1.16。+1 のときに線を越える割合は 1.2 万試合で 7 割半、2 万試合で 9 割ほど
