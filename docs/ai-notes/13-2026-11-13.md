## 伏せた相手の手札のスペルブーストを決定化で見込む（2026-11-13〜、審査の「次」の任意の項、ユーザーが選んだ。設計）

- **問い:** 決定化（`rust/engine/src/ai/determinize.rs`）は伏せた相手の手札を配り直すとき、手札で付いた状態（スペルブーストの回数・コスト変化・X）を 0 にする（[11](11-2026-11-01.md)「相手の伏せた手札のスペルブースト・コスト変化」）。
  公開の出来事から分かる範囲で回数を見込めば、問 `bishop-clear-g1689` の「ブーストのたまった鬼呼びの術と 2 枚目のクオン」を読みに入れられる。
  今の読みでは顔に行く手が 62.5%・全部取る手が 46.9%、スペルウィッチの手札を実際のままにすると 0% 対 25.0%（[12](12-2026-11-05.md)「ユーザーが調査からの 26 問を確かめる」）
- **守る線:** 実際の回数は覗かない。見る側に分かるのは、相手の手札の伏せた枠に起きた公開の出来事の順番だけ（どの枠から出したかは分からない。[rules.md](../rules.md)「手札から出したカードの位置」）
- **作り（案）:**
  1. エンジンは、プレイヤーごとに「手札の伏せた枠に起きた公開の出来事」の記録（`handLog`）を状態に持つ。ルールには効かない（`hiddenDiscards` と同じく、相手の AI の決定化のためだけ）。記録そのものに非公開の情報を入れない

     | 出来事 | いつ |
     | --- | --- |
     | 伏せたカードが入った（山札から引いたなら、引く前の山札の枚数も） | 引く・伏せたまま手札に加わる |
     | 伏せたカードが出た（スペルブーストやベイルでコスト・X・攻撃力が変わるカードなら、見えたコスト・X から分かる回数の範囲も） | プレイ・捨てる・融合の素材・公開になった |
     | 伏せたカードが山札に戻った | オーバーディメンション・マリガン |
     | 手札全部がスペルブーストされた（回数） | スペルをプレイした（ほかの手札に 1 回ずつ）・「手札のカードすべてをスペルブースト」（天后・オーバーディメンション等） |
     | 選んだ手札 1 枚がスペルブーストされた | 虹の奇跡（今のデッキには無い） |
     | 公開されていたカードが伏せた枠になった（そのときの回数） | 捨てる・戻すカードを選んだとき・出したカードと見分けがつかなくなったとき |
     | 味方のフォロワーが場を離れた | 煌撃の戦士・ベイルの「手札にある間」の能力 |

  2. 決定化は、記録を頭からなぞって、伏せた枠ごとの「スペルブーストを何回受けたか・味方が何回離れたか」を作る。枠は数だけを持ち、名前も iid も持たない。
     入った → 0 回の枠を足す。全部ブースト → 全部の枠に足す。出た → 枠を 1 つ抜く（どれを抜くかは乱数。回数の範囲が分かっていれば、その範囲の枠から）。
     山札に戻った → 枠を「山札に戻った枠」に移し、後で山札から引いたときに「戻った枠の数 ÷ 引く前の山札の枚数」の割合でそれが戻ってくる。味方が離れた → 全部の枠に足す
  3. なぞった後の枠を伏せた手札の枠にランダムに割り当て、配り直したカードに、その回数だけスペルブースト（と「味方が離れた」）をエンジンの処理でかけ直す。
     コスト・X・攻撃力・宿題やるですぅ！の変身はエンジンが出す（カードごとの処理は AI に書かない）。かけ直しは選択待ちの局面でも動くよう、写しの局面で解決して手札のカードだけ戻す
  4. 設定の項目（`oppHandBoosts`）にする。既定にするかは勝率で決める。物差しの凍結した相手（`reference_options`・`strong_reference_options`）では切って、指紋を動かさない。
     状態の比べ（ビームの同じ局面の判定）には記録を入れない（同じ局面に別の順番で着いても同じ局面）
- **近似（分かっていて入れないもの）:** 回数の分からないカードを出したとき、どの枠を抜くかは一様（高いカードほど長く持つ等の相関は見ない）。配るカードと枠の回数は独立。
  打ち比べの道具（`branch_playout`。調査・`misses duel`・`pick`）の最初の決定化は前のまま（変えると道具の数字が全部変わるので、別に決める）。マリガン・リーサル探索の決定化も前のまま（序盤・自分のターンなので効かない）
- **問題集の局面:** 今の問の局面には記録が無い（記録が無ければ今までどおり 0 回で配る）。記録のある問（`check` が打ち直す問）と、調査の試合から取った問（試合を打ち直して同じ局面になるのを確かめる）は、記録を入れて局面を書き直す。
  `bishop-clear-g1689` は `witch-storm-g1689` からの `duel --dump` なので、前の決定化で打ち直して同じ局面になるのを確かめてから記録を入れる

- **公開・非公開（ユーザー確認、2026-11-13。[rules.md](../rules.md)「伏せた手札のスペルブーストの回数（相手に分かること）」）:** 回数そのものは見えず、払ったコストと、能力で使う X（ダメージ等）から推理する。
  山札に戻ったカードを後で引いても、戻ったカードかは分からない。手札を 1 枚選ぶ効果は、選べるカードがあることだけが分かる。
  X は、盤面が空でダメージが出ない等で分からないこともあるが、今は分かる扱い（近似。ユーザーも今は気にしなくてよいとのこと）
- **作り（実装したもの）:**
  - 記録は `PlayerState::hand_log`（`state.rs` の `HandLog`）。局面の複製で中身を写さないよう、新しいものを先頭にした共有のリスト（自己対戦・探索の局面の複製ごとに記録を写すと遅いので）。
    JSON は `handLog`（空白区切りの文字列。形は `state_json.rs` の `hand_log_text`）、無ければ省く。正規化した文字列（ゴールデンのハッシュ）にも入る。ビームの同じ局面の判定（`keys.rs`）には入れない
  - 出したカードの記録（`HandEv::Out`）は、回数の範囲ではなく見えた中身（カード・コスト・X・攻撃力と体力の変化）を持つ。X は、手札で働く能力以外の能力が X を使うカードだけ（`card_shows_x`。能力のデータの JSON に `{"kind":"thisX"}` があるか。宿題やるですぅ！の X は見えない）
  - 回数の候補は決定化の側で出す（`determinize.rs` の `counts_seen`）: 手札で働く能力を持つカードを、作り直してから 0〜30 回スペルブースト（または味方が離れた）したときの見える中身を、エンジンの能力の解決で作り（`effects.rs` の `hand_feature_seq`、カードごとに 1 度だけ作って覚える）、見えた中身と同じになる回数を候補にする。
    変身した後の姿（成長したですぅ！）も、変身する前のカードの何回後の姿かで分かる。どの回数の姿にも合わないカード（ほかの効果でコストが変わった等）は、回数の分からないものとして扱う
  - 決定化（`determinize_with`・`determinize_apart_with` の hand_boosts、探索の設定 `oppHandBoosts`）は、記録をなぞった枠の数が伏せた手札の枚数と合うときだけ、枠をランダムに伏せた手札に割り当てて、回数だけきっかけを起こし直す（`reapply_in_hand`。写しの局面で解決して手札のカードだけ戻す）。
    記録に回数を変える出来事が無ければなぞらない（乱数も使わない）。切ってあれば前とまったく同じ（ゴールデンの AI の試合・物差しの指紋は変わらない）
  - マリガンで戻したカードも「山札に戻った」として記録する（回数は 0 なので見込みには効かない）
  - 問題集: 記録のある問 6 つは `npm run misses -- check --write-hand-logs` で記録を入れた局面に書き直した（打ち直した局面と記録だけが違う問だけを書く）。調査から取った問（`origin` が `state`）には記録が無く、今までどおり 0 回で配る

### 道具

- **compare・survey・beam-gap・profile の `--decks`**: デッキのファイルを何個でも、または `@<デッキの組>` で受け取る。n 個のデッキの試合番号 g の組は `i = g % n`、`j = (3g + 1 + g / n) % n`（7 個のときは今までと同じ組とシード。台帳の行とそのまま比べられる）。
  n² 個の試合番号で全部の組（同じデッキどうしも含む）を 1 回ずつ。同じ名前のデッキ（84 個では型とチームが同じものがある）には大会の名前を足して見分ける。既定のデッキ以外ではマリガンを簡単な方式（sample）にする（`td selfplay` と同じ）。

## 補正の学習を Rust に移す（2026-11-14、ユーザーの希望・審査の進め方。作りと確かめ、学ぶ補正は変わらない）

- **きっかけ:** ユーザーの希望（2026-11-14）で、補正の学習（`td train`）を速さのために Rust に移し、できればメモリも減らす。進め方と「確かめ」の線は審査が決めた（共有フォルダの `notes/train-rust.md`）。
  線は「同じデータ・同じ引数で、TypeScript 版と同じモデル（間引いた後と属性で埋めた後の重みが数値として一致）」。守ること: エンジンと探索は触らない、PC では回さない、夜のキューの `td train` の行の意味を黙って変えない
- **作り:** `svwb td train`・`td prune`（`rust/engine/src/runner/td_train.rs`・`td_data.rs`。使い方は [commands.md](../commands.md)「svwb」）。学び直しの流れ（`night/relearn-b.txt`）が使う引数だけを移した
  （`--epochs`・`--lr`・`--l2`・`--lambda`・`--holdout`・`--seed`・`--best`・`--bestOn`・`--ivRes`・`--ivWeight`・`--imaginedWeight`・`--base`・`--excludeDecks`・`--onlyDecks`・`--dropInputs` と、基本の `--batch`・`--fitA`）。
  実験用の引数（`--attr`・`--cmpWeight`・`--v1Only`・`--searchTarget`・`--seat`・`--exclude` 等）・場のカードのネットワークを持つモデル・属性の分を持つモデルの間引きはエラーにして、TypeScript 版に残した。`td attr` も TypeScript のまま。
  TypeScript 版は照らし合わせの元として残し、`npm run td -- train … --impl rust` と夜のキューの行の `--impl rust` で Rust 版を呼ぶ（既定は TypeScript 版のまま）
  - **データの持ち方:** 0 でない入力 1 個に 3 バイト（添字 16 ビット、値は入力の値の種類の表への 8 ビットの符号。種類が 256 を超えたら 16 ビット）、局面 1 つに 21 バイト（入力の始まり・次の局面・想像の局面の元・印 1 バイト・探索の値）と、`--base` が S を読むときだけ S の 8 バイト。
    royal-9 の 361 万局面で 468MB（1 局面 130 バイト。TypeScript 版は 590 バイトほどで、読む間の倍々の山がある）。`.gz` は `gzip -dc` で読み（依存は足していない）、行を 256 行ずつスレッドで読み取って、ファイルの順に足す
  - **一致させる所:** 足し算の順番は TypeScript 版のまま。`exp`・`log`・`**` は V8 と同じ値を返すもの（`rust/engine/src/jsmath.rs`。V8 の `ieee754.cc`（fdlibm を移したもの）を移した）。
    Rust の `f64::exp`・`ln`・`powf` は C ライブラリを呼び、Node 22 と比べて exp は 200 万個のうち 1 割、pow は `0.999 ** k` の 300 万個のうち 2% が 1 ビットずれた。移したものは pow の結果が非正規化数になる所のほかはビットまで同じ
    （V8 の pow は fdlibm と r の分母が 1 か所違い、そこも合わせないと 1% ずれた）。ミニバッチの並べ替えの乱数、AUC の並べ替え（同じ値の順）、書き出す数の丸め（`toPrecision(6)`）と JSON の書き方・キーの順も同じ
  - **並べ方（結果は変わらない）:** ミニバッチの中の局面ごとの前向きの計算と、出力から最初の隠れ層までの逆伝播（勾配を足す前まで）をスレッドに分ける。勾配を局面の順に足して Adam で更新するのは、重みの行ごとにスレッドに分ける
    （1 つの重みには TypeScript 版と同じ順に足す）。最初の層の行（入力ごと）のうちミニバッチに出ない行は勾配が 0 で、TypeScript 版も更新の式を毎回当てているので、その回の分を同じ式・同じ順で、行が次に出たときと全局面の予測の前にまとめて当てる。
    全局面の予測も局面ごとに分ける。スレッドの数（`THREADS`）を 1・3・4 にしても同じファイルになった
- **確かめ（TypeScript 版と、書き出したモデルのファイルを sha256 で比べた）:**
