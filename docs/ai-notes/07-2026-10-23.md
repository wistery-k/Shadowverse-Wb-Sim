## カードの重みを属性とカードごとの残りに分ける（2026-10-24、ユーザー案、学び直さない形を採用。一緒に学ぶ形は不採用）

- **きっかけ（ユーザー）:** いろいろなカードを試すとき、初見のカードもテキストとステータスからある程度それらしい重みで始まってほしい。
  今の補正は、学習データに出なかったカードの行を `td prune` で 0 にしているので、初見のカードは手書きの評価だけで見られている
  （ロイヤル対策 8 回目の初見殺しの半分もこれ）。プレイングの学び直し（デッキによらないうまさ）と、デッキを試す道具（両方の席が新しいカードを知っている補正）の両方に効く
- **形:** 補正の最初の層のゾーン z・カード c の行を W1[z,c] = Σ_k 属性 k(c) · A[z,k] + R[z,c] と見る（ゾーンごとに属性の重み A、カードごとの残り R）
  - 属性（`scripts/cardAttrs.ts`、今のカードで 156 個）: 切片（カード・クレスト）、種類、クラス、トークン、コスト（数と 0〜10 の別）、攻撃力・体力、
    アミュレットのカウントダウン、キーワード・攻撃回数・土の印・エンハンス（`src/engine` と同じ読み取り）、タイプ、能力の定義から: きっかけ（ファンファーレ・進化時 等）、
    効果のプリミティブ、きっかけ × プリミティブ（「ファンファーレでダメージ」「進化時に召喚」等）、条件（コンボ・エンハンス・覚醒 等）、
    ダメージ（相手のリーダー・全体・1 体）・回復・ドロー・召喚するフォロワーの攻撃力 + 体力・バフ等の量。テキストは使わない。vocab の 3 項目以上が持つ属性だけ
  - 最初の層は線形なので、A と R を足してカードごとの行に戻して書き出す。推論（Rust）は変えない
  - `npm run td -- attr`: 学び直さずに、学んだ行（0 でない行）にゾーンごとのリッジ回帰（罰 λ、切片は罰しない）で A を当てはめ、学んでいない行を属性の分で埋める。
    そのゾーンに現れえない行（スペルの場の行、アミュレットの攻撃力の行 等）は 0 のまま
  - `npm run td -- train --attr 1`: A と R を一緒に学ぶ。A は当てはめから（モデルに A があればそこから）、R は今の行 − 属性の分（学んでいない行は 0）から始める。
    学習データに出なかった行は R = 0 のまま、つまり属性の分だけ。A の勾配は行の勾配を属性で足したもの。R の減衰は `--l2Res`、A は `--l2Attr`（どちらも既定は `--l2`）。
    書き出すモデルは A（`attr`）も持ち、`td prune` はそういうモデルなら、データに出なかったカードの行を 0 でなく属性の分にして A を外す

  - **全部のデータで一緒に学ぶ（rfa）:** 今の既定に 46.5%（±0.9）、rf（同じデータを今の形で学んだもの）に今の 7 デッキで 46.9%（±0.9）、新しいデッキで 45.5%（±1.0）。採用しない
  - **まとめ:** 知らないカードを属性で補うのは学び直しても効く（hc +3.6、hb +6.0 ポイント）。一緒に学ぶ形は、知らないカードには埋めるだけの形より少し良い（予測も勝率も）が、
    知っているカードの学びを悪くする（今の 7 デッキで −1.9・rfa は −3〜−4.5 ポイント）。既定は埋めるだけの形のまま（学ぶときは今の形で学び、その後に `td attr`）
  - **見当:** A の 1 つの成分は、その属性を持つ多くのカードの行に足される。Adam は成分ごとにほぼ lr の幅で動かすので、1 枚の行は属性の数（十数個）倍の幅で動き、
    実質の学習率が大きすぎる。A の学習率だけ下げる `--lrAttr`（A の学習率 = lr × lrAttr、0 なら A を当てはめたまま動かさない）を足して確かめた
- **`--lrAttr` の確かめ（クラウド、2026-10-24）:** 確かめ用の自己対戦 c0（14 デッキ 2000 試合）の前の 1500 試合で s2b から学び（3 エポック、`--best 1 --bestOn end,imagined`）、

  - 後ろの 500 試合（ターン末・最初、今の形との差、± 0.004 ほど）: lrAttr 1 −0.009、0.3 −0.011、0.1 −0.011、0.03 −0.011、0 −0.011。属性ありはどれも今の形より良いが、

## 補正はカードごとの EP の価値を学んでいるか（2026-10-24、ユーザーの質問。リーアムのように進化時効果の強いカードがあると EP を重く見るべきでは）

- **測り方（`td probe --ep 1`）:** EP が残っているターン末の局面で、EP を 1 減らしたときの補正の下がり（EP 1 つの価値、評価の点数）を出し、
  手札（`--zone myBoard` なら場）のカードを 1 枚抜くとそれがどれだけ変わるかをカードごとに平均する。`--minMaxPp k` で PP 最大値 k 以上の局面だけ
- **学んでいる:** 補正の入力には手札のカードと EP の数が両方あり、隠れ層で組み合わせられるので、カードごとの EP の価値は学べる。実際に学んでいて、
  rf（ユーザーの PC、f0・f1 の 1.4 万局面）では EP 1 つの価値は平均 32 点、手札のカードで −6〜+6 点動く
  （上がる: シルヴィア +6.2・バックウッド +5.4・ボーンガール +4.2、下がる: バーンドナイト −6.3・メドゥーサ −6.3・ロデオ −6.2・ジェノ −6.1）。
  デッキによる違いの方が大きい（スペルウィッチの局面では 12〜18 点、エルフでは 45 点前後）。今の既定（s2ba）も似た形（クラウドの c0 で、rf とカードごとの値の相関 0.87）
- **リーアムは上がらない:** rf で −0.7 ± 0.2（363 局面）、クラウドで c0 から学んだ補正の PP 最大値 7 以上の局面で −0.8 ± 0.1（90 局面）。
  探索の手書きの評価の evoReserve（手札の進化時能力持ちを EP の数まで 1 枚 3 点）を足しても +2 点ほど
- **理由は構造でなくデータ:** クラウドの c0（s2b どうし 2000 試合）で、人形ネメシスがリーアムを引いた 254 試合のうち、出さずに終わったのが 206 試合、
  出したのが 48 試合（進化させたのは 28 試合）。リーアムが場にいて進化していないターン末は 28 局面で、EP が残っていたのは 1 局面だけ。
  コスト 10 のリーアムが出る頃には EP はたいてい使い切っていて、「リーアムのために EP を残した」局面が自己対戦にほとんど無いので、補正は学びようがない。
  「手札のカード × EP が残っている」を入力に足しても、この局面が無いことは変わらない（入力を足す案は見送り）
- EP を残すかどうかはデッキの回し方の問題で、確かめるなら、手書きの規則（例: 人形ネメシスはリーアムが手札・山札にあれば終盤まで EP を 1 つ残す）を入れた AI と今の AI で勝率を比べる

## 環境を自動で回す（`svwb meta`、2026-10-24、ユーザーが方向の案 1 を選んだ。道具とクラウドでの通しまで。本番はユーザーの PC）
