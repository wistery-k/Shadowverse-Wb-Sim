## 相手の手札読み（2026-10-13）

- **きっかけ:** ユーザー案。相手の手札を一様ランダムで作るのをやめ、確定している情報は追う・1 枚で大きく動くカード（クオン、ガリュウ、ケルベロス等）を想定する
- **今の作り:** determinization（`src/ai/determinize.ts`）で、相手の手札（トークン以外）と山札をデッキの未公開カードから並べ直す。3 サンプルそれぞれで自分のターンを探索し、上位 4 手は相手のターンを貪欲法で 1 回ずつ読む
- **公開情報の追跡（採用。正しくする修正）:** AFネメシスのアーティファクト等のトークンは前から残していた。漏れていたのは、場から手札に戻ったカード（エルフの自分のバウンス、セルウィン）、名前の決まったカードを効果で加えたもの（探偵のルーペ）、手札で変身したもの。
  これらを `HandCard.revealed` として記録し、並べ直さない。条件付きで引いたカード（「フォロワーを 1 枚引く」等）は条件を `HandCard.drawnBy` に記録し、条件に合うカードを割り当てる。どちらもルールには影響しない（ビームの同じ局面の判定でも見ない）。効く場面は少ないので勝率は測っていない
- **選んだ手札を隠す（2026-10-22、正しくする修正）:** 手札から捨てる・山札に戻すカードを選んだとき、相手にはどれを選んだか分からない（ユーザー確認、`docs/rules.md` 11章）のに、
  AI は捨てたカードを並べ直す候補から外し（どれを捨てたか分かる）、公開済みのカードやトークンが手札に残ったかどうかも分かっていた。
  手札から捨てる・山札に戻すカードを選んだとき、候補だった手札のカードの `revealed`・`drawnBy` を消す（改境の再動のように、選んだカードのコピーを出すなど相手に分かる選択では消さない）。相手に分からない捨てたカードは `PlayerState.hidden_discards`（JSON では `hiddenDiscards`）に残し、
  determinize で伏せた手札・山札と合わせて並べ直して、残りを捨てたカードとする。トークンを常に公開とみなすのもやめ、`revealed` だけで決める（効果で加えたトークンは `revealed` を持つ。
  山札から引いたトークン、アポカリプスデッキから引いたカードは並べ直す側になる）。どれもルールには影響しない。効く場面は少ないので勝率は測っていない
- **上限の測定（`peekOppHand`）:** 自分のターンの探索で相手の手札を実際のまま使う（山札の順番と乱数は並べ直す。リーサル探索は今のまま）。`npm run compare -- 400 '{"peekOppHand":true}' '{}'` で **52.6%**（421/800、標準誤差 ±1.8%）。
  相手の手札が完全に分かっても +2.6 ポイントほど（有意とは言えない）で、手札の推定をどれだけ良くしてもこれ以上は伸びない。
  デッキ別ではロイヤル 69%、ウィッチ 60% が高く、AFネメシス 45%・エルフ 33% は伸びていない
- **引き直して平均（`oppHandSamples`）:** 上位の手を相手のターンまで読むとき、相手の手札・山札を 4 回引き直して相手のターンを打ち、評価を平均する（大きく動くカードを、持っている確率に見合った重さで読みに入れるため）。
  `npm run compare -- 400 '{"oppHandSamples":4}' '{}'` で **48.1%**（385/800）。1 試合 0.26 秒 → 0.34 秒。伸びないので既定は 1（引き直さない）
- **手札を見る＋相手のターンを探索（ユーザー案）:** 手札が見えても相手のターンの読みが貪欲法のままでは、相手が大きく動くカードを上手く使う読みにならず、上限を低く見ている可能性を確かめた。
  `npm run compare -- 400 '{"peekOppHand":true,"opponentSearch":{"beamWidth":4,"maxDepth":8}}' '{}'` で **53.9%**（431/800）。
  それぞれ単独（52.6%・52.3%）の伸びを足した程度かそれ以下で、組み合わせて大きく伸びることはなかった。上限は合わせても +4 ポイントほど
- **結論:** 手札読みは今の AI の伸びしろとしては小さい。相手の行動からの推定（安いカードを出さなかったら持っていない、マリガンで残しそうなカード等）は、上限が +3 ポイント弱なので今は進めない

## 手順どうしの比較で、評価関数が見ていないものを探す（`plan-value`、2026-10-13、測定のみ）

- **きっかけ:** ユーザーの質問（評価関数がまだ見ていない重要な指標の見つけ方）。カード 1 枚を抜く介入（card-value）は「持っている価値」を測れても、「今出すか後で出すか」の比較には使えなかった（手札 2.0 で 1 ターン目のアミュレットを出さなくなった）。
  評価関数が実際に使われるのは同じ局面の手順どうしの比較なので、そこを直接測る
- **方法（`npm run plan-value-data` / `plan-value-fit`）:** 探索 AI どうし（エルフはリノセウス用 AI）の対戦で、自分の 2〜8 ターン目の最初の局面を取り出す。探索 AI の候補（最初の手ごとのターン末の最善の並び、相手のターンを読む前）の上位 4 つを作り、
  合流する相打ちの後でターンを終え、同じ 16 個のシードで（視点のプレイヤーから見た決定化をしてから）探索 AI に最後まで打たせる。局面ごとに平均を引いてから、勝率と評価関数の点数・特徴を比べる（デッキ・先攻後攻などの交絡が消える）。
  リーサルのある局面と、点数が ±1e6 になる候補を含む局面は除く
- **規模:** 500 試合の予定が、2 時間の上限で 290 試合（530 局面、集計に使えたのは 479 局面・1791 候補）で止まった。1 局面約 13 秒（4 並列で）で、見積もり（約 10 秒）より遅かった
- **結果（全デッキ。エルフを除いても同じ傾向）:**
  - 局面の中の勝率の違いのうち、続きの誤差を除いた分を評価関数がどれだけ説明できるか: ターン末の点数 45%、相手のターンを読んだ後の点数 39%。評価 1 点 ≒ 勝率 +1.2〜1.3%
  - 選び損（探索 AI が選ぶ候補と、続きで勝率が最も高い候補の差。続きを半分に分けて推定）: +0.2%。上位 4 手順の中から選ぶ段階では、評価関数を直しても 1 回の判断で取り戻せる分は小さい（この推定は誤差で 0 に寄るので下限）
  - 評価で説明できない残りを特徴 1 つずつで当てはめると、|t| の大きい順に: ターン末の残り PP（1 につき −2.2%、t −6.9）、相手の打点−自分の体力（−2.2%）、相手の体力計・攻撃力計・フォロワー数、自分の最大攻撃力より体力が多い相手のフォロワー（−5.8%）、相手の最大攻撃力より体力が多い自分のフォロワー（+3.5%）
  - 主な特徴をまとめて当てはめると（`notes/plan-value/joint.py`）、評価点に換算して: 残り PP 1 につき −2.4 点（t −4.0）、自分の体力 1 につき +3.2 点（t 3.9、体力が変わる候補は少ない）、手札 1 枚 +2.3 点（t 2.3）、自分のフォロワー 1 体 +3.7 点（t 2.5）。相手の場の 3 つは互いに似ていて、1 つずつは有意でない
- **見立て:** 手札 1 枚の価値が今の 0.6 より高いのは card-value（換算 2.1 点）と同じ。手札の重みだけを上げると出さなくなったが、残り PP の罰と組み合わせれば「PP を使って出す」ことは損にならない。次に試すなら「ターン末の残り PP の罰 ＋ 手札の重みを上げる」を勝率で比べる
- 全表・データは共有フォルダの `notes/plan-value/`（fit.md、fit-no-elf.md、joint.txt、data.jsonl）。data.jsonl は 4 並列で同じファイルに追記したため、1 行が壊れている（集計では飛ばす）

### ターン末の残り PP の罰＋手札の重みを上げる（`ppLeft`、不採用）

- **きっかけ:** 上の plan-value で、評価が同じでも残り PP の多い手順ほど勝率が低く、手札は評価より高い価値だった（ユーザー了承で試した）
- **変更:** 重み `ppLeft` を追加。自分のターンを終える局面の残り PP 1 につき引く。探索 AI のターン末の採点（ビーム）と、上位の手を相手のターンまで読み直した点数にだけ効き、`evaluateWith`（貪欲法・相手のターンの読み）では見ない。既定は 0。
  手札の重みを上げるときは、融合で作るカードの価値（hold）も同じ倍率にする（`npm run compare` の `"holdScale"`）
- **結果（`npm run compare -- 400 '<設定>' '{}'`、相手は今の AI、各 800 試合、標準誤差約 1.8 ポイント）:**

  | 設定 | 勝率 |
  | --- | --- |
  | 罰 2 | 403/800 = 50.4% |
  | 罰 2・手札 1.2（hold 2 倍） | 408/800 = 51.0% |
  | 罰 2・手札 2.0（hold 3.3 倍） | 405/800 = 50.6% |
  | 罰 1・手札 1.2（hold 2 倍） | 411/800 = 51.4% |

- **結論:** どれも誤差の範囲で、採用しない。手札 2.0 は罰と組み合わせると 1 ターン目のアミュレットの件のような崩れはなくなった（50.6%）が、伸びもしない。
  plan-value で上位 4 手順の中での選び損が +0.2% しかなかったことと合う。評価の残りが特徴で説明できても、上位の候補の中の順番はほとんど変わらない。
  伸びしろがあるとすれば、上位 4 つに入らない手順（候補の作り方）か、相手のターンの読みの方だと思われる（推測）
- **ユーザーの見立て（試した後）:** PP が余るのは「PP をドロー・盤面などに変換できていない」「重いカードを消化できず後の動きが悪くなる」ことの表れで、余らせること自体が負けの原因ではない。罰はその表れを直接たたくだけで、浅い理解になっている。
  plan-value の特徴の当てはめも、手順の中の相関なので、残り PP は「その手順で得られなかったもの」の代わりに出ていた可能性が高い。探すなら、変換できたものの価値（何を引けたか、場に何が残ったか）や、手札に残る重いカードが後のターンを詰まらせるか、の方
- 結果の出力は共有フォルダの `notes/ppleft/compare.txt`

## 人間の手順と AI の手順を打ち比べる（`human-plan-value`、2026-10-14、測定のみ）

- **きっかけ:** 人間の対戦記録 61 試合で人間は 50 勝、同じ試合を当時の AI が打つと 27 勝。今わかっている伸びしろ（相手読み +2.3pt、手札読みの上限 +2.6pt）より桁違いに大きい。
  人間の記録から見つけた案は効いたもの（sevoReserve・lastWordsSummon）も外れたもの（器のマリガン・kerberosReserve 等）もあり、どの違いが勝敗に効いたかが分からなかった。
  plan-value で「上位 4 手順の中の選び損は +0.2%」だったので、残る伸びしろが探索と評価のどちらにあるかも確かめたい
- **方法（`npm run human-plan-value` / `human-plan-value-report`）:** 人間の記録を再生し、人間の自分のターンの最初の局面ごとに、人間のターン末と、同じ局面から AI（エルフはリノセウス用 AI、他は探索 AI）が打つターン末を作る。
  それぞれから同じ 32 個のシードで（人間側から見た決定化をしてから）探索 AI に最後まで打たせ、勝率の差を取る（plan-value と同じ）。マリガンも 0 ターン目として比べる。
  あわせて、人間の手順のターン末の点数が AI の候補（最初の手ごとの最善の並び）の最善より高いか（ビームが届かなかった）を記録する。続きは探索 AI が打つので、次のターン以降に向けた人間の狙いは低めに出る（下限）
- **規模:** 61 試合・650 局面（手順が違ったのは 408）、4 並列で 92 分
- **結果:**
  - 手順が違った局面の差の平均 +3.4% ± 0.8%。1 試合あたりの差の合計 +22.6% ± 5.4%（実際の勝率の差 38 ポイントの 6 割ほど）
  - デッキ別（違った局面の平均）: エルフ +9.6%、AF +2.8%、ビショップ +2.5%、ナイトメア +2.4%、ウィッチ +1.2%
  - 差の合計の内訳: 評価が AI の候補を上に見た局面 91%（345 局面、+3.7%。262 局面で人間の手順は点数で負けていた）、ビームが届かなかった局面 17%（16 局面、+15.0%）、マリガン −7%（42 局面、−2.3% ± 1.9%）
  - ターン末の特徴の差（手札・EP・SEP・残り PP・自分と相手の場の攻撃力と体力・両者の体力・評価の点数）をまとめて当てはめても、切片 +6.0%（t 6.2）が残る。人間の手順の良さは全体の量では説明できず、どのカードをどう使ったかの中身にある
  - 手の種類（超進化・進化・プレイ・攻撃・融合）ごとに見ても、1 つの種類に偏らない
- **見立て:**
  - マリガンは人間に寄せても伸びない（mulligan4 と同じ結論）
  - 探索の幅で取り返せるのは残りの 2 割弱
  - 大半はカード・局面ごとの判断の誤りで、全体の重みや特徴の項では直らない（ppLeft・手札の重み・キーワードの定数が効かなかったのと合う）。効いた sevoReserve・lastWordsSummon もカード固有の知識だった
  - 差が +25% 以上の 33 局面の一覧（共有フォルダの report.md）は、どの違いが勝敗に効いたかを因果的に確かめたもの。人間の記録の分析は、この一覧の上から見るのがよい
- 全表・データは共有フォルダの `notes/human-plan-value/`（README.md、report.md、data.jsonl、features.txt、actions.txt）

### 人間の手順が大きく勝った局面を 1 つずつ見る（`human-position`・`variant-plan-value`、2026-10-14）

- **きっかけ:** 上の report.md で差が +25% 以上の 33 局面を上から見て、評価の誤りを探す（ユーザー了承。ドラゴンは人間と AI の差が小さいので加えない）

- **見立て:**
  - **対照:** 同じ AI でも乱数だけで 3 割の局面の手順が変わる。全局面の平均は 0 で道具に偏りはないが、差の大きい局面だけを選ぶと元の AI の手順はたまたま悪い方を引いたものが多い（平均への回帰）。

  - **計画の使い回し（reusePlan）がいちばん大きい:** 使い回しは、手を選んだ 3 サンプルのうち評価が最も高かったサンプル（相手の手札が最も都合のよい決定化）の並びを 2 手目以降もそのまま打つ。

  - 相手のターンの探索（対戦で +2.3pt）が +0.4% ± 0.4% で、道具の向きは対戦と合う
  - oppFuse は Ω の局面（体力 7 で回復しない）を 0/32 → 31/32 に直すが、変わるのは AF が相手の局面だけで、全体では小さい。dangerRescore は、上位の手がすべて負けと読まれる局面がほとんどなく効かない

  食い違ったら次の手で探索し直す。変わる局面は 15% で、使い回さない場合の 6 割ほどを取り返す
- **reuseAgree の勝率（不採用）:**

  - ふるい分けでは全局面で +0.6% ± 0.2%（z 約 3）、1 試合の合計 +6.1% だったが、対戦では差が出なかった。遅くなるだけなので採用しない（設定は既定の無効のまま残す）

## 探索 AI の評価の重みを勝率で調整する（`npm run spsa`、2026-10-14、不採用）

- **きっかけ:** 人間の記録の局面の分析・予測精度・ふるい分けのような代わりの指標から選んだ案は、勝率で何度も外れた。勝率そのものを目的にして、1 つずつでは測れない小さな効きをまとめて拾えないかを試した（ユーザー了承。「未着手の候補」にあったもの）
- **方法（SPSA、同時摂動確率近似）:** SEARCH_WEIGHTS のうち正の値の重み 29 個（oppHp は尺度の基準として固定。閾値・0 の重み・カードごとの hold は動かさない）を、SEARCH_WEIGHTS からの倍率の対数 x で表す。
  毎回、全部の x を同時に ±c（±20%、回とともに少しずつ小さく）ずらした 2 つの重み（+ と −）を作り、compare と同じ組み合わせ（7 デッキ、席とデッキを入れ替え）で 56 試合直接対戦させる。
  + の勝ち越しから勾配を推定して x を動かす（歩幅 a 0.4・A 30・指数 0.602、x は ±2 まで）。毎回新しい試合番号（g100000〜）を使う。採用の候補は後半 150 回の x の平均
  - 並列化: 仕事の一覧が前の結果で決まるので、何度も仕事を渡せる Worker の集まり（`createPool`、scripts/parallel.ts）を足した。compare の試合の組み方は `playCompareGame`（scripts/compare-main.ts）として共通にした
- **規模:** 300 回・16,800 試合、4 並列で 84 分（1 回約 17 秒）
- **調整後の重み（後半 150 回の平均、今の値からの倍率）:** SEP 5 → 8.2（×1.64）、キーワード ×0.61、アミュレット ×1.29、土の印のアミュレット ×1.27、攻撃力 ×0.79、fusionSet ×0.76、kuonReserve ×0.84、他は ±20% 以内
- **結果（`npm run compare -- 400 '<調整後>' '{}'`、調整に使っていない g0〜799）:** g0〜399 407/800、g400〜799 402/800、合わせて **809/1600 = 50.6%**（標準誤差 ±1.25 ポイント）。伸びていない
- **調整の途中:** 1 回ごとの + の勝率の標準偏差は 6.4〜7.7%で、56 試合の二項分布のばらつき（6.7%）とほぼ同じ。全部の重みを同時に ±20% 動かしても、勝率は測れるほど変わらない（勾配がほぼ無い）。
  上の倍率の動きの大半は、ばらつきによるものと考えられる（推測）
- **結論:** 全デッキ共通の重みは、今の値のまわり（±20%）でほぼ平らで、全体の重みを動かしても伸びない。plan-value・human-plan-value の「全体の重みや特徴では直らない」と合う。
  調整後の重みは採用しない。残っているのは、デッキごとの重み・カードごとの価値（hold）のように、デッキやカードに固有の項
- 調整の記録は共有フォルダの `notes/spsa/`（run1.jsonl・run1.log・validate.txt）

## ブラウザも WASM にし、TypeScript 版のエンジン・AI を消す（段階 4、2026-10-15）

- **やったこと:** ブラウザ（対戦・AI対戦・リーサル表示）と Node のスクリプト（`npm run sim`・`game`・`sim-report`・`td` 等）が、
  Rust のエンジン・AI を WASM（`rust/wasm`）にしたものを使うようにし、TypeScript 版のエンジン（`src/engine` の効果の解決等）と AI（`src/ai`）を消した。
  TypeScript 側に残したのは、局面の型・能力の DSL・カードの定義、AI のデータ（重み・マリガンの表）、WASM を呼ぶ薄い関数（`src/engine/game.ts`・`src/ai/registry.ts`）
- **使わない実験のスクリプトは移さず消した（ユーザー判断）:** `npm run bench`・`plan-value`・`human-plan-value`・`human-position`・`variant-plan-value`・
  `lethal-prevent`・`spsa`・`tune`・`mulligan-data`/`fit`/`eval`/`model-fit`。必要になったら main の d0dd121 の TS 版を見て Rust に移す
- **TS 版との一致の確かめ方を置き換えた:** 決まった試合（ランダムな手の試合と、探索 AI・`search-classic`・リノセウス用 AI・貪欲法・ランダムの AI どうしの試合）の結果を
  ゴールデンテスト（`rust/engine/tests/golden/*.txt`。`cargo test --release`）として保存した。TS 版を消す前に、その結果が TS 版との差分テストで一致することを確かめてある。
  以後は保存した結果と比べる。振る舞いを意図して変えたら `npm run svwb -- golden write` で保存し直す
- **AI のテストを Rust に移した:** TS の AI の単体テスト（探索・評価関数の各項・リーサル探索・リノセウス用 AI とリーサル問題集・マリガン・同じ局面の判定・学習した補正等）を
  `rust/engine/src/ai/tests/` に移した（73 件）。TS 版にしか無かった実験用の設定（`exhaustive` 等）のテストは設定ごと消した
